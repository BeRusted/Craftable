# M4 增补：共享配方知识与有界持久缓存

- 日期：2026-09-12。
- 状态：2026-09-12 共享关系、有界缓存、自动回归及开发交付已完成；冷预览/性能样本限制与待完成的人工验收见 [实施进展](17-m4-progress.md)。
- 决策：[ADR-0007](adr/0007-shared-recipe-knowledge.md)。继承 [M4 规格](14-m4-spec.md)、[实施计划](15-m4-implementation-plan.md) 的资源、预算及事务边界。
- 核心原则：长期复用“如何获得物品”，每次重新计算“当前资源如何分配”。知识缓存不是第二套配方系统，也不是历史执行计划。

## 1. 当前实现与实际增量

下表“已有行为”指 2026-09-12 增补前基线；共享关系和磁盘边界现已实现，最终验证记录见实施进展：

| 当前位置 | 已有行为 | 本次增量 |
|---|---|---|
| `CraftingRecipes.Index` | 按 RecipeManager/运行时配方世代复用 byId、byOutput、规范化 Entry/Requirement | 在原索引内共享 Ingredient 与生产候选关系，不复制配方目录 |
| `CraftingRecipes.producing` | 已按产物查找；每次仍枚举材料选项、合并去重、校验匹配并按 ID 排序 | 对可规范化的相同需求复用完整、有稳定顺序的候选邻接表 |
| `CraftSearch` | 现物快路径、有界回溯、独立数量账本、请求内记忆化 | 消费同一共享邻接信息；保留现物优先和必要回溯 |
| `CraftSearch.reachableItems` | 从本次库存出发，反复扫描目录得到忽略数量的存在性闭包；仅同一资源视图内共享 | M4.7 未另建反向邻接；09-13 修订为放宽的材料存在性预筛，不以此授权权限，实际候选展开仍检查工作站/解锁 |
| `PlanView` | 从实际计划/诊断生成有界显示投影，也调用 producing | 复用同一知识入口，不另存所有目标的展开树 |
| `CraftingSessions` | 保存短期状态、意图、确认摘要和 MAX 进度 | 不承担磁盘知识、长期路线或可执行计划存储 |

增补前没有磁盘知识缓存；本轮已将按需学会的完整候选邻接持久化，而非保存每个目标的展开树。成功方案历史仍未实现。原有按产物索引一直存在，本轮减少的是重复关系合并，不是替换一个原本盲搜全部配方的系统。

## 2. 共享图的最小模型

逻辑上采用“产物 → 候选配方 → 输入需求 → 可选材料”的共享关系；物理上沿用 Index、Entry、Requirement 与引用表，不引入通用图框架。

- 每个配方 ID 对应一个 Entry，保留真实配方句柄、槽位/重复需求、完整批次产量、精确输出及所需网格能力。
- 相同语义的输入需求共享一个规范化键及生产候选列表。多个配方使用“木棍”时引用同一列表；单个物品本来就可被多个 Ingredient 接受，不复制其生产配方。
- 一个配方的全部输入是 AND；一个 Ingredient 接受的材料及一个目标的多种生产配方是 OR。不能把多条配方的输入拼成一个平面材料表。
- 保留木板/竹子两种木棍配方、不同原木的木板配方、钻石块拆解等候选，不在知识层选定玩家应该走哪条路线。
- 铁锭↔铁粒、钻石↔钻石块的环正常保留；知识构建不递归展开路径，不因有环而删除配方。现有求解预算及分支循环检查仍负责终止。
- 根批次、需求数量、已消费物、生成余量及来源归属属于 CraftSearch/ResourceLedger。共享知识不能把同一木棍抵扣两次。
- 仍调用真实 `matches`、`assemble`、`getRemainingItems` 验证实际步骤。静态图不能承诺输入相关的产出/剩余物，更不能授权特殊配方。

M4 只为当前已支持的普通原版有序/无序配方建立知识，不顺带支持炉类、交易或第三方配方。受支持 ID 被数据包覆盖、标签成员变化仍必须正确失效，这不是承诺通用数据包支持。

### 2.1 Ingredient 键与缺失项

仅对当前支持且能证明语义稳定的普通 Ingredient 规范化：记录规范化类型及排序后的完整匹配选项，包含实际匹配所需的组件语义；不能只用标签名字、首个物品或对象 hash。实现前以固定版本的实际 Ingredient 行为验证键的等价性。

无法证明可规范化的需求沿用现有精确 producing 路径，不猜测等价关系。共享候选列表是静态稳定顺序；求解器按当前账本排序时使用本地视图，不原地修改全服列表。

M4.7 实现取证修订（2026-09-12）：NeoForge 21.1.235 自带的原版箱船、漏斗等配方使用 `DifferenceIngredient`，不能以 `isCustom()` 一概排除后导致整个原版知识库无法持久化。明确允许已核对源码的 `CompoundIngredient` / `IntersectionIngredient` / `DifferenceIngredient`，但仅当全部叶子仍为普通 Ingredient，且结构遍历有界时，按其实际已解析物品集合规范化。其他自定义条件（包括自称 simple 的类型）仍不共享；组件、数量或动态条件不得被压成物品 ID 集合。这是固定平台内置集合表达式的窄适配，不是第三方材料 SPI。

缓存允许按需学习并保留完整邻接项，无须首次启动展开所有目标。必须区分“这个键还没有建完/没有缓存”和“已完整计算且没有生产配方”。时间或容量不足时不发布半个候选列表；未命中走原索引，有界查询未完成则返回搜索限制，不能缓存成永久无解。

## 3. 三种生命周期不能混合

| 数据 | 作用域/寿命 | 能否写入知识文件 |
|---|---|---|
| 规范化需求、配方 ID、静态候选关系、知识指纹 | 同一服务端配方世代；同一存档可跨重启 | 可以，且仅作为可重建缓存 |
| 实际 RecipeHolder/Ingredient、注册表对象 | 当前服务端/注册表运行期 | 不可以；启动后由当前索引重新绑定 |
| 容器位置/句柄、库存数量/组件栈、玩家解锁、工作站可用性、规则、可生产集合 | 当前请求或相同身份的短期资源视图 | 不可以 |
| 可合成三态、缺口、MAX 下界、分支失败、确认令牌、可执行 CraftPlan | 既有短期会话/一次求解范围 | 不可以 |

邻接关系可在同一服务端玩家间共享；玩家 A 的解锁、末影库存或成功结果不能变成玩家 B 的知识授权。知识内可记录“需要 3×3”，不可记录“附近现在有工作台”。

资源变化不删除知识；知识变化必须使引用它的旧预览、确认、MAX 进度失效。即使 `/reload` 后内容指纹相同，也开启新的运行时世代并重新绑定句柄，不能让旧令牌跨重载执行。

## 4. “永久”的保留边界

永久表示“无时间 TTL，条件不变时可跨重启复用”，不是不可删除的数据资产，更不是存档玩法进度。

### 4.1 所有权与文件

- 存放在当前存档的 Craftable 专属缓存子目录，已实现相对位置为 `craftable/cache/recipe-knowledge-v1.json`。集成服务器与专服遵循同一规则，不写客户端全局目录、不跨存档混用。
- 每存档只保留一个当前快照和至多一个有界临时文件；不按目标、玩家、重载次数累计历史文件。
- 文件只包含格式版本、稳定内容指纹、校验信息及有界的 ID/需求/邻接记录。无库存、坐标、玩家 UUID、活对象、执行指令或完整展开路径。
- 可由维护者在停服后删除本模组这一缓存文件，下次重新学习；不能需要“迁移成功”才能打开世界。世界备份是否包含它不影响玩法正确性。
- 不新增玩家玩法设置、清理 UI、数据库依赖或配置框架。实现时的日志仅报告世代、命中/失效原因、大小与耗时，不打印玩家资源。

### 4.2 内容指纹

运行时对象身份只用于本次进程的快速世代判断；跨重启指纹必须在配方和标签加载完成后，从权威数据生成，不能每次 C 全量计算。

指纹至少覆盖：

1. 缓存格式和规范化/支持规则版本，以及 Minecraft、NeoForge 版本。
2. 当前支持边界的完整配方集合：稳定排序的 ID、类型/序列化器、规范化配方内容；同 ID 的输入、排列、产量、组件变化均能被发现。
3. 参与匹配及安全准备判定的已解析标签/注册表语义；包括嵌套标签实际成员变化与移除。
4. 任何真正改变知识抽取或支持范围的规则版本/配置。检测半径、库存和玩家解锁等请求条件不进入静态指纹。

仅比较 ID 数量、数据包名、文件时间或模组版本不合格。序列化必须确定性规范化，不受 Map 迭代顺序影响；无法稳定表达的条目不持久化。具体固定版本的数据读取/重载挂接在 M4.7a 取证，不先引入未来适配器 API。

跨 JVM 实测修订：金苹果的默认食物组件含 `MobEffectInstance.Details` 的 `neoforge:cures` 集合，底层 `setOf` 的序列化数组顺序不稳定。规范化规则版本升为 v2：仅在已知食物/药水效果及其 hidden_effect 路径排序此集合；不排序输入、效果序列或 custom_data 内任意同名数组。文件格式仍为 v1，旧规则指纹自然失效，不要求迁移旧缓存。

### 4.3 失效、损坏与写盘

- 当前配方管理器是唯一真值。文件指纹匹配仍须校验格式、内容校验、引用存在性、候选与 Ingredient 匹配、邻接完整性和各级上限，再绑定当前 Entry；不能盲信磁盘声明的“完整”。验证成本计入基准。
- 指纹不匹配、文件损坏/截断/非法引用、读写拒绝、未知版本或超限，均忽略该缓存并从原索引按需重建；不使合成更宽松，也不把缓存失败当作材料不足。
- 缓存缺失时允许直接使用现有按输出索引，不能为等待磁盘而卡住 C。新关系项只有完整构建才可发布；旧运行时世代不可与新目录混用。
- 采用同目录临时文件、完整校验后原子替换；若平台不能安全替换，就放弃此次落盘，不先删除有效快照。合成事务不等待写盘完成。
- 新增知识脏标记合并写入，正常运行最多每 30 秒一次，正常关闭尝试保存；进程异常终止可能丢失最近学到的缓存项，只导致重算，不导致物品丢失。
- 若需要后台文件 I/O，只处理复制好的不可变原始数据；不访问玩家、世界、RecipeManager 或执行配方。每服务端至多一个在途写入及一个合并待写快照，不能建立无限写队列；过期世代不得覆盖新世代文件。

### 4.4 容量和计算边界

已实现硬上限（不是玩家配置项）：指纹范围最多 16,384 个配方记录、16,384 个规范化需求键、262,144 个材料选项引用和 262,144 个需求→生产配方引用；单文件 16 MiB、单 ID 512 ASCII 字节；身份快捷表最多 4096 项。文件格式不压缩，流式固定结构解析在分配前限制条目和文件大小；原文件及临时文件各有 16 MiB 上限。超出持久化配方范围不截断原索引，而是只使用内存。

新增知识缓存的估算驻留内存以 64 MiB 为起始上限，须报告实际峰值；不把估算当 JVM 硬内存保证。计数/字节任一超限即停止新增缓存，未缓存项走原索引，不删除实际配方、不截断成错误的不可合成。旧文件与临时文件合计也有明确上限。

新增关系构建、验证和反向邻接工作计入既有请求/后台预算；完整候选项可分批准备但不能把未完成项当无配方。指纹/磁盘加载放在服务端加载或重载生命周期，并单独报告耗时；不将全图构建偷偷放在每个玩家首个按钮的 8 ms 预算之外。若必须引入新的主线程分片，先验证最小生命周期方案，不保留活世界搜索任务。

## 5. 每次合成怎样使用知识

1. 新鲜取得当前可用资源、工作站、权限与规则，根目标和手选约束不变。
2. 沿用现物快路径。已有 2 根木棍且补齐 3 钻石时，下一把镐的实际计划仅消费这些现物，不出现木板/原木制作步骤。
3. 缺口通过原索引的共享候选关系查找；知识未命中才建立关系，不展开并永久保存整棵目标树。
4. 在本次账本中分配精确数量、来源、余量和剩余物；候选按当前资源重新评估。
5. 无法满足后续需求时保留必要回溯。“先用现物”不等于永远锁死贪心选择，例如某木板同时是标签材料和另一配方的唯一特定材料时，需允许重新分配。
6. 输出当前合法计划，沿用容量模拟、确认复验和唯一事务；搜索超时仍是未知，不因为图中有路径就染绿或部分消费。

忽略数量的存在性闭包仅是剪枝辅助。09-13 修订在闭包中放宽权限、在候选展开时检查权限，以免把无材料起点的锁定转换误当目标锁定。当前库存起点、实际工作站/解锁判断、AND 需求满足计数仍不可持久化。无库存的转换环不能自行激活；有起始铁粒的合法转换也不能因永久 visited 被拒绝。

### 5.1 2026-09-15 浏览生命周期增补（待实现）

[M4.8/M4.9](20-m4-filtering-and-client-planning.md) 将原动态闭包/状态从单批扩大到同一不可变资源版本。权威配方/标签在服务端，两端使用原 Index 的同一规范化/索引代码，各自维护按配方世代复用的关系图；磁盘缓存只在服务端。客户端关背包/换分类不销毁静态图，重连或配方世代变更才重绑。默认本地构建并先测一次构建成本，不默认同步服务端已学关系；必要时须比较传输、校验和重建总成本后再决策。

动态优化先保持现 reachableItems 算法、实现同版本闭包只建一次，再独立计时；若仍为瓶颈，才在原 Index 增加材料→需求/配方邻接并替换扫描算法。此邻接不意味着实现资源改变后的局部失效。来源引用稳定、授权复查无变化只续期，不重算闭包和完整证据；现活配方/玩家回调留在服务端边界。完整失败/未知和分片/重试规则以主设计 3.5、5.1 为准。

动态资源、容量、授权版本、闭包和可行见证仍不写入知识文件，不跨玩家共享授权，不新增客户端永久缓存。反向邻接用于优化原闭包时属于索引实现细节；基于反向图的局部结果失效和成功历史仍延后。M4.7 原文件与规则指纹无需仅因新增网络同步而升级；若规范化语义真的变化才按原失效契约处理。知识指纹不能替代连接/运行时世代。

## 6. 历史成功路线：保留接入位置，不在 M4 建库

成功路线历史属于 M8 的可选启发式实验，与 M7 的 Z 撤销日志完全不同。当前不建空接口、空存储器或占位配置，接入位置仅指定在现有求解器候选排序处。

若后续实测值得实现：

- 只记录已成功提交的配方选择及紧凑共享依赖引用，不记录源槽、库存、计划或已执行次数；解释页路径字符串不是跨世代稳定键。
- 作为现物优先之后、用户硬约束之内的候选排序提示，不能排除其他候选、放宽权限或跳过实际组装。
- 本次提示尝试与回退共享原预算；失败或不适用即回到普通候选，不能额外跑一轮完整预算。预算未完成仍诚实返回未知。
- 默认考虑玩家隔离、世代绑定、每目标少量候选及总容量淘汰；不得让甲玩家的偏好静默支配乙玩家消耗。具体持久范围与上限届时再定。
- 同路线重复、路线交替、资源迁移三组对照同时测命中率、回退成本、P95 和有效回答率；出现净退化就不启用。

## 7. M4 是否现在做：结论与顺序

建议在 M4 关闭前完成共享关系和最小磁盘缓存，新增 **M4.7**，之后再进行本次完整人工复测。理由是两者直接服务当前递归/详情入口，现在收紧边界比 M5 扩大配方类型后改造更容易；但不扩大求解目标，不与历史学习一并开发。

### M4.7a 基准与失效契约

- 记录现状：索引构建次数、producing 调用/候选合并次数、关系构建时间、资源闭包时间、账本搜索状态/分配、图投影、MAX 重试及端到端延迟。
- 固定重启、重载、标签与同 ID 覆盖夹具；验证规范化键与指纹，给出磁盘验证的真实成本。
- 这是实现前门禁，不先写通用序列化层。旧的 43 JUnit/55 GameTest 是 2026-09-10 基线，不是新机制已通过的证据。

### M4.7b 原索引内共享关系

- 在 Index 内规范化/共享邻接项，由 producing 对外提供；CraftSearch 与 PlanView 共用它。
- 同世代、同需求在未达容量上限时最多完整构建一次；跨玩家、移动、箱子变化、查询目标变化不重复学习。
- 反向邻接仅在测得闭包扫描成本值得优化时接入；不另建求解器。失败/超限保留原索引路径。
- 正确性与“关系构建次数不随重复请求增长”通过后，才加入持久层。

### M4.7c 最小持久缓存

- 实现上述文件、指纹、验证、世代及故障降级。只序列化已完整学会的共享关系，不要求先学完全部目录；已保存关系跨重启复用，未学关系按需补全。

## 8. 新增验证门禁

自动化至少覆盖：

1. 镐/梯子等共享木棍候选；不同木材、竹子候选不丢失，重复查询不重复合并；槽位重复与配方批量不被去重掉。
2. 第二次镐直接使用余下木棍；标签/特定物品竞争仍能回溯；partial 不重复准备；完整/余料/剩余物守恒不变。
3. 移动、换容器、两玩家不同库存/解锁/工作站：共享知识不重建，但当前可合成结论分别更新。
4. 保存、正常停服、重新启动后有效关系命中；同 ID 改输入/产量、只改标签、增删配方、版本变化均拒绝旧缓存；相同内容重载仍拒绝旧令牌。
5. 截断/校验错误/未知格式/假完整邻接/非法引用/超大文件/超量记录/写入拒绝/替换失败/过期写回：无崩溃、无假无解、无错误物品变更，原索引仍可用。
6. 未缓存与已证无生产配方可区分；预算半途结束不污染共享空结果；有起点/无起点转换环、未知与真缺料区分保持。
7. 关服后知识状态释放；不同存档/新集成服务器不串用运行时对象；无后台常驻轮询与无界队列。
8. 原 M2/M3/M4、10000 固定种子图及客户端/专服回归保留；自动测试补充量按风险，不用凑测试数量代替覆盖。

性能对照使用相同配方/库存/预算与固定请求序列：空缓存首次、同进程重复、更换资源、跨重启命中、数据重载；包含钻石镐、混合木材 MAX、宽分支、转换环、1/16/64 容器、单/双玩家。报告 P50/P95/P99/最大、有效回答/截断率、分阶段耗时、关系命中/构建次数、缓存与内存峰值、完整 tick 和冷启动增量。暖态重复各至少 100 次、冷启动各至少 5 次，记录硬件、JVM、RTT，不用单次最好值作结论。

门禁保留普通状态/简单详情 P95 500 ms 目标和既有预算；不得通过放宽预算制造加速。结构复用必须可证明，性能若无净收益必须公开并定位瓶颈，不能因“有持久图”就宣布性能问题全部解决。
