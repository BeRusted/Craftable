# M1 严格实施计划

- 状态：已完成（2026-09-02）
- 目标版本：Minecraft 1.21.1 / NeoForge 21.1.235
- 前置结论：[M0.2 验收报告](07-m0.2-acceptance.md)

## 1. M1 唯一目标

建立一个服务端权威、可配置、可缓存、可诊断的纯原版工作环境快照，使后续 M2 执行器与 M3 配方书只依赖同一份环境契约。

M1 结束时必须能回答：

1. 当前玩家的扫描边界是什么；
2. 哪些原版资源端点被纳入，端点 ID 是否稳定且唯一；
3. 当前有哪些工作站能力；
4. 这份结果属于哪个单调递增的环境世代；
5. 客户端请求是否只表达目标，而没有伪造资源或工作站；
6. 管理员如何在不打印具体物品内容的情况下检查上述结果。

## 2. 明确不做

以下内容不得借 M1 顺手加入：

- 不修补 M0.2 的配方书双重状态、完整目录或 3×3 实体菜单；这些属于 M3；
- 不补齐配方剩余物、并发托管和完整事件语义；这些属于 M2；
- 不实现递归规划、部分完成、熔炼、撤销或可达性寻路；
- 不引入 JEI、`IItemHandler`、领地模组或任何第三方兼容；
- 不发布通用兼容 API、动作提供者 SPI 或持久化数据库；
- 不增加每 tick 扫描器、后台线程或新区块加载；
- 不替换 `Player.inventory`、`InventoryMenu` 或客户端屏幕。

发现上述需求时，只记录到对应里程碑，不扩张 M1。

## 3. 模块所有权与依赖方向

```text
config       只定义经过边界校验的客户端/服务端设置
workstation  只定义原版工作站能力与稳定来源
environment  扫描、端点、快照、短缓存和世代；不得依赖 client/execution
network      只传目标 ID、请求序号和结构化结果；不得传资源槽位
execution    消费快照；创建请求必须取得新快照
client       发送意图并展示结果；不得决定服务端资源真值
command      只读诊断环境摘要；不得修改世界或输出具体物品内容
```

允许的核心依赖是 `execution -> environment -> config/workstation`。反向依赖、跨包静态回调和客户端类进入服务端路径均视为架构偏移。

## 4. 核心不变量

### 4.1 服务端权威

- 客户端请求只包含配方 ID 和无语义请求序号；
- 客户端不能提交端点、槽位、数量、工作站或判定结果；
- 预览可以使用短缓存，创建操作必须重新扫描；
- 创建成功或环境复验失败后立即使预览缓存失效。

### 4.2 快照

- 每份快照包含维度、原点、扫描设置、生成时刻、世代、资源端点和工作站端点；
- 同一快照中端点 ID 必须唯一；
- 世代由服务端按玩家单调递增，不复用世界时间；
- 快照和其中的活容器句柄只允许在服务器主线程短期使用，不持久化、不跨线程；
- 玩家跨方块、跨维度、设置变化、缓存超时或显式失效后不得复用快照。

### 4.3 扫描

- 只访问已经加载的区块；
- 只接受 `minecraft` 命名空间的原版方块容器；
- 玩家主背包固定为 0..35，不含护甲与副手；
- 双箱只产生一个规范端点；
- 未生成战利品、无法无副作用验证锁权限、物理上不可打开或已经失效的容器被排除；
- 锁检查不得调用会播放声音或发送提示的 `canOpen`；
- 配置有严格上限，防止扫描体积失控。

### 4.4 网络

- 协议版本在载荷结构变化时递增；
- 响应回显请求序号，客户端忽略过期响应；
- 结果使用稳定枚举，不把服务端异常文本直接发送给客户端；
- 限流按玩家生效，退出后清理状态。

## 5. 配置预算

M1 只注册以下配置：

服务端：

- 水平扫描半径，默认 8，范围 1..16；
- 垂直扫描半径，默认 4，范围 0..8；
- 预览快照缓存 tick，默认 5，范围 0..20；
- 是否把附近末影箱作为个人末影库存入口，默认开启。

客户端：

- 是否启用当前原版配方书增强入口；
- 是否显示详细制作失败反馈。

没有实际消费者的配置不得提前加入。

## 6. 实现顺序

1. 建立配置值对象和 NeoForge 配置注册；
2. 建立 `WorkstationCapability`/`WorkstationEndpoint` 与新版 `EnvironmentSnapshot`；
3. 把扫描半径、末影箱策略和无副作用锁检查接入扫描器；
4. 建立按玩家缓存的 `EnvironmentSnapshotService`，定义预览与强制刷新入口；
5. 让直接合成只通过快照服务访问环境；
6. 网络协议加入请求序号与单调环境世代，客户端丢弃过期响应；
7. 注册 `/craftable environment` 只读管理员命令；
8. 增加模型、唯一性、缓存策略、请求时序和限流清理测试；
9. 运行单元测试、完整构建和专用服务端启动验证。

## 7. 注释规则

关键注释解释“为什么存在约束”，重点覆盖：

- 为什么快照不能跨线程/长期保存；
- 为什么创建必须强制刷新；
- 为什么锁检查不能调用原版 `canOpen`；
- 为什么请求序号不参与服务端业务判断；
- 为什么调试命令不输出具体物品。

简单 getter、枚举值和直接赋值不写重复代码的注释。

## 8. 完成标准

- 配置文件能由 NeoForge 正确加载，且所有数值在构造模型前已有上限；
- 相同有效缓存条件返回相同世代，失效或强制刷新产生更高世代；
- 快照拒绝重复端点 ID；
- 创建路径没有使用预览缓存；
- 客户端无法通过载荷指定资源来源；
- 管理员命令能看到范围、世代、端点和工作站摘要，普通玩家无权限；
- 单元测试、完整 Gradle 构建和专用服务器类加载验证全部通过；
- 路线图和验收记录与代码一致。

实施结果与验证证据见 [M1 验收报告](09-m1-acceptance.md)。
