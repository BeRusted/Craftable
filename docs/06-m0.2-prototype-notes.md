# M0.2 原型实现说明

> 状态：原型已于 2026-09-02 完成验收并冻结。本文描述原型实现，不代表最终产品行为；正式结果见 [M0.2 验收报告](07-m0.2-acceptance.md)。

## 1. 当前已经成立的能力

- 背包配方书在附近存在工作台时以有效 3×3 尺寸执行原版背包材料判定，但不修改玩家菜单槽位拓扑；该做法已被验收证明不足以覆盖附近容器状态和左键虚影；
- 不批量解锁配方，配方书显示扩展不会写入玩家原版解锁进度；
- 客户端悬停配方时只发送配方 ID，材料、工作站和结果均由服务端计算；
- 服务端扫描半径为水平 8 格、垂直 4 格，并且不加载新区块；
- 资源端点包含玩家主背包、附近原版方块容器，以及附近存在可打开末影箱时的个人末影库存；
- 普通箱与双箱按一个端点处理；锁住、被阻挡或带未生成战利品表的容器保守排除；
- `C` 可执行一个普通原版有序/无序直接合成；执行前检查材料和输出空间，提交时再次验证槽位，并在异常时恢复提交前内容；
- 状态与制作请求有服务端限流，附近库存不会发送给客户端；
- 已通过 Java 编译、单元测试、纯 NeoForge 专用服务端启动，以及集成客户端进入世界并实际加载全部 Craftable 配方书 Mixin 的验证。

## 2. 原型有意不承诺的能力

- 尚无递归合成，因此箱中只有原木时还不能自动得到木棍并制作钻石镐；
- `PARTIAL` 状态的数据通路已经存在，但在递归规划器完成前不会把“仅拥有部分最终材料”误报成可部分执行；
- 配方剩余物、特殊/动态配方和模组配方会返回“不支持”，避免错误消耗；
- 当前直接配方材料分配采用稳定的贪心顺序，复杂替代材料的回溯选择属于 M2；
- 尚未实现 NeoForge `PlayerEvent.ItemCraftedEvent` 的完全等价上下文；当前只结算原版物品制作统计与配方成就触发，完整事件语义属于 M2；
- 回滚当前针对原版同步主线程容器；多人竞争、故障注入和 GameTest 仍是 M2 的发布门槛；
- 当前半径常量只是原型值，配置与更高级可达性检测分别进入 M1 和第二阶段；
- 不包含 JEI、第三方容器、领地模组或额外工作站兼容。

## 3. M0.2 原始客户端验收矩阵

1. 无工作台时，背包配方书不把钻石镐视作有效 2×2 配方；
2. 放置附近工作台后，钻石镐出现在配方书中并显示 Craftable 状态边框；
3. 钻石和木棍分散在玩家背包、单箱和双箱时，按 `C` 只制作一个钻石镐；
4. 拿走一个输入、封住箱盖、锁住容器或填满玩家背包时，服务端拒绝并给出对应反馈；
5. 搜索框聚焦时输入 `C` 不触发制作；不同 GUI 缩放下悬停目标保持正确；
6. 退出到专用服务端后不发生客户端类加载错误。

实际测试中，第 2 项只在材料位于玩家背包时成立；第 3 项的 `C` 执行成立，但附近容器材料不会进入原版 `showing craftable` 集合。完整逐项结果和根因已转入正式验收报告。
