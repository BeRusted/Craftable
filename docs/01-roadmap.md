# 实施路线图

## 1. 为什么重排原始两阶段

递归规划器如果没有“选择目标”的通用入口，就无法自然完成“鼠标指向钻石镐并直接制作”这一核心体验。Craftable 不再自行开发一套 JEI 风格主浏览器，而是把原版配方书前移为第一阶段核心前端：

1. **原版配方书增强**：复用搜索、图标、分页和分类，加入 3×3 环境语义、三态显示与 `C` 操作。进入第一阶段早期。
2. **统一计划解释**：原版配方书和 JEI 都展示会消耗什么、使用什么工作站、缺什么。与递归规划器同步完成。
3. **生态扩展**：第二阶段把更多模组配方、非标准动作和工作站 UI 接入原版配方书，同时完善 JEI 前端。

第一阶段专注纯原版体验，不让 JEI 或其他模组兼容反向支配核心架构。核心稳定后再在第二阶段接入 JEI；届时不会禁用、隐藏或降级原版配方书增强，两个前端始终调用同一服务端能力。

1. **M0.2-A 原版配方书原型（部分通过，完成技术取证）**：悬停目标、有效 3×3 尺寸、`C` 请求和服务端状态显示均可注入；同时证实“额外描边”不会改变原版 `craftable` 集合与过滤，解锁集合不能承担 `ALL` 目录，伪装 3×3 尺寸也不能正确驱动 2×2 菜单虚影。

3. **M0.2-C 直接合成事务（核心路径通过）**：服务端能从附近容器消耗材料并完成一次普通原版有序/无序合成；配方书显示异常不影响服务端权威执行。

验收结论：M0.2 作为“验证危险假设”的技术原型通过并关闭，但不能作为可发布功能通过。三个已确认缺口转为 M3 的强制验收项；详见 [M0.2 验收报告](07-m0.2-acceptance.md)。JEI 和第三方容器不阻塞 M0 或第一阶段核心开发。

### M3 原版配方书增强（已验收，2026-09-08 关闭）

实现契约及范围校准见 [M3 严格实施计划](12-m3-implementation-plan.md)，验证证据见 [M3 验收报告](13-m3-acceptance.md)。A–G、虚影修正及 H 玩家反馈通过；连续切换分类后约 2 秒状态收敛、配置分类翻译缺失与旧日志单次服务端延迟作为非阻断跟踪项保留，不宣称零警告或全负载性能保证。

- 复用原版配方书的图标网格、搜索、分页、分类和多配方切换；
- 从客户端已同步的配方目录建立独立显示集合；`ALL` 不依赖原版解锁集合，也不修改玩家解锁进度；
- 按可见页批量取得同一环境世代的权威三态，把结果写入配方集合筛选语义，而不是在原版红框外追加另一层颜色；
- 配方页打开、翻页或搜索后主动预取可见按钮状态，不以鼠标悬停作为首次出现绿框的前置条件；
- `showing craftable`、分类可见性、按钮样式、工具提示和 `C` 必须读取同一状态；
- 创建响应后将已有状态标记待确认，只主动刷新当前视图；输出容量是共享约束，因此不引入材料依赖图进行精细失效；
- 生存/冒险附近工作台时提供客户端与服务端一致的真实 3×3 背包，复用原版背包人物、纹理、装备位置；左键放置、虚影、结果槽和 Shift 点击使用同一槽位拓扑；
- 实体工作台的配方书同样增强；创造/旁观完全禁用菜单请求、按钮、状态预取和 C，切换模式安全返还，回生存须下次正常打开；
- 工作台消失、玩家重生/切维度/切换游戏模式时安全刷新或关闭菜单，不替换 `Player` 的库存对象；
- `C` 键执行一次配方；“制作最大数量”随 M4 的数量规划和输出容量语义实现；
- 可合成/部分可合成/不可合成三态及无障碍可区分样式；
- 建立统一反馈路由：状态留在按钮/Tooltip，普通成功不弹文字，主动失败使用可合并的原版 Toast，复杂计划进入可阅读面板；
- 通过 NeoForge 公开屏幕事件评估在原版“选项”页加入 Craftable 设置直达入口；入口只复用同一个配置页，不复制配置控件；
- 多人环境显示服务端有效规则摘要，不把客户端本地 `SERVER` TOML 当作服务器真值；
- 不通过批量解锁配方污染原版进度；`ALL/UNLOCKED_ONLY` 只控制显示策略。

验收：无 JEI 环境中，玩家不查命令也能完成钻石镐示例；材料分别位于背包与附近容器时，无需逐个悬停即可取得按钮状态，按钮状态、`showing craftable` 结果和 `C` 行为一致；成功创建后的刷新不出现虚假的短时红框；左键预览在实体 3×3 中无错位。

基础筛选全范围延迟必须在 M4 关闭前解决，不推迟到 M8。M8 只保留后续规模化刻画、反向依赖局部失效和历史启发式。不上两套搜索算法或并行的服务端全目录/客户端全目录计算系统，不通过提高预算或隐藏未知项“优化”。

## 4. 第二阶段：智能与扩展

### R1 存储资源端点增补（独立子线，未实施/待排期）

- R1a：玩家持有或已授权工作环境中存在末影箱方块物品时，可作为访问本人末影库存的钥匙；保留既有可用方块入口，不全世界找远处末影箱，不从未授权末影库存自授权。
- R1b：潜影盒、收纳袋等明确支持的便携内容；先确定载体根身份/内部路径、去重、嵌套/同步上限、载体与内容互斥及组件写回/整体补偿，不能仅把内部物品平铺成普通来源。
- R1 不依赖先实现 M9 的检测几何或实体扫描；它解决存储所有权与写回，而 M9 解决环境检测范围/可达性及实体竞态。

- 记录槽位变化、精确物品组件、输出位置、经验和端点版本；
- 任一相关状态已变化则拒绝撤销并解释原因；
- 初期只支持纯物品合成，随后再评估熔炼经验与世界交互。

### M8 智能路径与燃料优化

- 扩展性能观测：低配硬件、大目录端到端、多容器 × 多设备 × 高 RTT、长期 P99/堆峰值；明确尚未证明，不与 M4 普通功能/安全验收混淆；

- 可选成功路线提示：按重复/交替路线基准证明净收益后再做，只影响候选优先级，不保存执行授权；复用 M4.7 知识入口，与 M7 撤销历史分离；
- 可逆配方识别和惩罚权重；
- 原料保留偏好、收藏/锁定材料和配方黑名单；这是求解策略，不与 M6 的个人配方收藏浏览功能混同；
- 按请求批量联合优化燃料，而非逐件贪心；
- 向玩家展示选择该路径的原因。

### M9 高级环境检测

- R1 存储资源端点是独立子线，不把便携载体写回/个人末影准入混称为检测模式升级；
- `BOX`、`EUCLIDEAN`、`LINE_OF_SIGHT`、`REACHABLE` 四种模式；当前 M1 有界方盒扫描明确记为 `BOX`，不误称欧式距离；
- 主线程分时的有界可达性搜索；
- 方块变化、区块卸载、维度变化和玩家移动触发失效；
- 掉落物、运输矿车等实体资源端点；
- 拾取冷却、所有者、年龄和实体死亡竞态处理。
- 在世界规则中加入检测模式、距离/搜索预算、是否使用掉落物和是否使用实体库存；单人可编辑，远程多人只读服务端有效值。

### M10 动作提供者

- 村民交易：职业、等级、库存、补货、折扣、声望和输入槽语义；
- 生物互动：剪羊等显式白名单动作；
- 世界规则提供实体动作总开关，并为村民交易、剪羊等不同副作用动作提供独立子开关；未实现动作不出现在设置中；
- 每类动作独立定义前置条件、副作用、冷却、声音/统计和撤销能力；
- 默认不把任意右键交互自动转成“配方”。

### M11 生态兼容与配方书扩展

- 仅在核心体验稳定后验证 JEI 公共 API，并提供与原版配方书一致的 `C`/`Z`、三态和计划解释；原版增强始终保留；
- 发布稳定的工作站/动作适配器 API；
- 为高需求模组编写独立兼容模块；
- 将更多第三方配方类型、村民交易和显式生物互动映射为可展示的原版配方书条目或动作条目；
- 在背包界面加入或兼容更多工作站的必要 UI、状态和配方分类；
- 原版配方书和 JEI 均接入 `Z` 撤销、历史及一致的状态刷新；
- 纯原版配方书、原版配方书 + JEI 两种环境的功能对齐测试。

## 5. 每个里程碑的通用完成标准

- 功能只在服务端验证后事务化提交；
- 新语义有单元测试，涉及世界状态的行为有 GameTest；
- 专用服务器验证通过，不只测试集成客户端；
- 玩家可见文本有 `zh_cn` 和 `en_us` 本地化键；
- 调试日志不泄露其他玩家私有容器内容；
- 没有每 tick 全立方体扫描；
- 新兼容逻辑失败时降级为“不支持”，而不是猜测执行。

## 6. 后续产品决策点

- 是否以及何时选择首批领地/权限模组与工作站模组；这不是第一阶段核心的前置条件。

这些选择不会阻止先实现服务端规划核心，但会影响 UI 和公开兼容承诺。
