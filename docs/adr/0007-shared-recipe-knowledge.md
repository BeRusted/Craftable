# ADR-0007：共享配方知识与可重建的持久缓存

- 日期：2026-09-12。
- 状态：M4.7 已实现；实际自动验证与人工验收状态见 [实施进展](../17-m4-progress.md)。成功路线历史推迟到 M8 按收益评估。
- 详细设计：[共享配方知识](../19-m4-recipe-knowledge.md)。补充 ADR-0006，不替代其求解与事务约束。

## 背景

现有 CraftingRecipes 已按产物建立世代索引，并非每次从全部配方盲搜。但 producing 仍重复合并材料的生产候选；知识也未跨重启保存。当前资源变化会使数量计划失效，却不应使“木棍可以用木板或竹子做”的关系失效。

为每个目标永久保存展开树会重复存储公共依赖并放大分支；缓存完整成功计划又会错误绑定库存、权限、容量和来源。因此需要严格区分静态知识、临时搜索与执行授权。

## 决策

1. 扩充现有 Index 的共享需求/候选邻接，不建立第二套配方目录、图数据库或求解器。配方保留 AND 输入、OR 候选、槽位与完整批次语义；环保留，搜索仍有界。
2. CraftSearch 和 PlanView 经同一个 producing 入口消费关系。先用现物，但允许材料争用所需回溯；动态数量、可生产集合、权限和可行性每次按当前上下文计算。
3. 知识缓存属于同一存档，条件不变时无 TTL、跨重启复用；每存档只保留一个有界快照。可以删除重建，不是玩法存档数据。
4. 指纹覆盖当前支持配方的规范化内容、解析标签、相关注册表语义、平台及抽取规则版本；ID 相同不表示配方未变。重载开启新运行时世代，旧句柄/确认/预览不复用。
5. 磁盘只保存版本、指纹、ID 与完整关系记录。未缓存不等于无配方；文件损坏、失配、超限或 I/O 失败回到原索引，不降级成缺料或跳过校验。
6. 知识不保存库存、位置、玩家、可合成状态、MAX、分支失败、令牌或可执行计划；真实配方调用、容量检查和整链事务完全保留。
7. M4 增加 M4.7：先测量与键/世代验证，再做内存共享、最小磁盘缓存，最后回归及 A–I 人工复测。2026-09-10 自动结果仅作为改动前基线。
8. recipe/planner 生产顶层类预算由 8 调整为最多 9，仅新增一个专职磁盘缓存边界类；不增加通用图引擎、持久任务管理器或历史学习占位实现。
9. 成功路线仅预留现有候选排序接入位置，M8 有净收益证据才实现；不把它混入 Z 撤销日志。即使命中历史也必须重新分配、验证，且与回退共享预算。

## 代价与不承诺事项

新增指纹、磁盘验证、大小上限和重载测试成本。跨重启校验有时可能与重新建关系一样贵，必须测量并评审，不以弱校验换速度。共享图减少关系探索，不消除数量组合、容量非单调、混合 MAX 或最优性问题。

正常合并写入前进程异常终止可能丢失刚学到的知识，只允许增加下次计算量。任何故障不得影响物品正确性。既有协议/菜单/客户端不因服务端知识缓存而改变；未来类型扩展再按对应里程碑演进。

## 明确不采用

- 每目标保存所有展开路线或永久 item-ID visited。
- 将成功计划、来源槽或“曾经可合成”作为下次执行依据。
- 按库存变化清空静态知识，或按知识未变长期保留旧绿状态。
- 只用 ID 数量/文件时间判断跨重启兼容。
- 为历史提示额外增加一轮完整搜索预算，或提前搭建通用学习框架。
