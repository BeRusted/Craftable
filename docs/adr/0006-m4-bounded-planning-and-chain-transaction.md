# ADR-0006：M4 有界需求规划与整链单次事务

- 日期：2026-09-08。
- 状态：采纳并实施中，尚未通过全部 M4 门禁；预算校准与回归记录见 [实施进展](../17-m4-progress.md)。
- 依据：M1 端点、M2 补偿事务、M3 状态与菜单契约，以及 [M4 行为规格](../14-m4-spec.md) 和 [游玩交互修订](../16-m4-interaction-and-performance.md)。本轮用户反馈已更新以下决策。
- 2026-09-12 增补：[ADR-0007](0007-shared-recipe-knowledge.md) 的原索引共享关系及有界持久缓存已按 M4.7 实现；这不放开持久执行计划、任务系统或通用图框架限制。当前验证状态见实施进展。

2026-09-15 设计增补：[ADR-0008](0008-snapshot-scoped-client-planning.md) 在待实现的 M4.8/M4.9 中窄化替代“预览不发送任何资源”“确认必重搜索”：允许最小授权值投影和完整固定量见证的新鲜验证。禁止客户端槽位写指令、未经校验产量、持久执行计划、搜索未知触发部分等约束不变。下文仍记录原 M4 决策，不代表新机制已经实施。

## 背景

当前执行器仅处理一次普通原版配方。直接递归调用 `createOne` 会分别提交中间步骤，破坏整链失败恢复；为未来机器构造通用 RecipeAction 引擎又会让兼容层反向主导原版基础体验。M3 还观测到连续切分类后约 2 秒预览收敛，不能把单根递归预算直接乘以整个可见页。

旧草案将“一块木板制两根木棍”作为部分完成示例，不符合完整配方批次；“全局最大有用前沿”和最佳优先超图搜索也超出当前必要规模。

## 决策

1. 根目标保持具体配方，单击 C 只尝试一次完整根批次；同目标失败后的双击才是部分意图，长按不算。高级数量在物品链页滑槽选择，根产物绝不丢弃。
2. 普通配方索引 + 有界需求回溯 + 可回退精确资源账本；先找可行计划，暂不做通用机器适配器和全局最优求解。
3. 单步与多步共用一个计划/事务入口，有序步骤列表足够。整个请求一次托管/提交，逐步通知延后到全部物品成功提交后。
4. 部分完成是有证据、有数量界限的成功计划，不是提交失败或超时后的前缀。默认 EXPLICIT_SAFE，仅在显式部分意图下使用安全白名单，未证明全量不可行时不自动降级；撤销未实现的单击 AUTO_SAFE 方案。
5. 预览不授权执行；显式确认用限时一次性意图/摘要令牌，确认重新规划，不缓存跨 tick 可执行活计划。
6. 规划预算同时约束根目标、批次与全服；单次原版调用不可抢占，必须测完整请求与 tick。M4.0 先取证，M4.4 集中处理单次/联合 MAX/预览效率，再接完整 UI。性能证据决定是否引入短期只读状态的主线程分片，不提前建设持久任务系统。
7. 详情升级为物品链页：工作站状态、可编辑生产配方、数量滑槽与改链警告。图是计划/诊断投影，更换节点配方后重算全局材料分配，不新增服务器菜单、配方浏览器或第二套执行系统。
8. 净交付默认全部入包；可选只把溢出余料按原版主动丢弃表现生成实体。中间物不逐步占实际背包格，但只允许在一次有界同步事务内托管；不引入隐形持久库存。实体创建成功/失败清理须进入同次提交门禁，不能提交物品后不检查地丢余料。
9. 根配方和用户手选节点约束不因 MAX 静默改变；自动支路允许联合使用多种配方。最大量未证明时只报可行下界；路线改变先显示 ! 与实际消耗并确认。

## 拒绝的替代方案

- 连续提交单步：失败后难以区分合法部分完成与被迫半完成。
- 为需要的 2 根木棍拆分原版配方：改变材料成本与产量。
- 根据物品 ID 做永久 visited：会漏掉有库存起点的合法可逆转换。
- 搜索超时就自动做已找到的中间步骤：可能错过完整路径并过度消耗资源。
- 简单把全部 MAX 请求逐个按完整预算试一遍：使数量上限变成耗时放大器。
- 预览返回完整库存、确认接受客户端槽位计划：扩大信息暴露并破坏服务端权威。

## 代价和限制

不保证全局最优；复杂/动态配方与不完备搜索可能拒绝合法手动路径。非默认组件材料保护、请求开始时每步已解锁仍收窄自动支持范围，必须有明确提示。撤销逐步中间空间限制是一项公开的操作压缩取舍；余料生成真实实体后可丢失/被他人拾取，不承诺可追回。没有 Z 前显式快速准备只限低风险路径，用户/服务端可收紧到确认或禁止。

所有候选决策、示例、边界和测试门禁以规格与实施计划为准；此 ADR 不把 M4 预留设计描述成已实现能力。
