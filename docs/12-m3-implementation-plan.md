# M3 严格实施计划：原版配方书增强与实体 3×3 背包菜单

- 目标版本：Minecraft 1.21.1 / NeoForge 21.1.235
- 前置状态：M2 已完成并通过局域网人工验收
- 状态：M3.0–M3.4 已实现并于 2026-09-08 验收关闭；自动验证、玩家两机复测及非阻断观察项见 [M3 验收报告](13-m3-acceptance.md)。

## 实施后的范围校准

具体契约见 [ADR-0005](adr/0005-m3-recipe-book-and-menu.md)。下列调整替代后文原始计划中对应表述，其余边界保持不变：

- 仅可合成筛选还需轮询当前分类/搜索的隐藏候选，否则未知条目永远不能进入筛选；可见页优先，仍限制为每批 32 个 ID、至少间隔 4 tick、单个在途批次。
- 制作会影响公共输出容量，故使已有状态全部待确认，仅重查当前视图；不为定向失效新建依赖图。相同结果刷新不增加显示版本，不重建页面。
- 配方书折叠但原版背包仍打开时，每 20 tick 发空列表探测工作台，以支持在界面打开期间放下工作台。关闭整个背包后停止；不会后台查询所有配方。
- 8 ms 是快照取得后、逐配方之间检查的软预算，不是包含扫描和单个求解的硬时限。截断批次优先补齐仍在当前视图的未答条目。
- 临时菜单沿用 `CraftingMenu`，槽位 ID 不变；复用原版背包 176×166 纹理及人物渲染，护甲/副手保持原版坐标，九宫格放在右上，输出在其下，配方书按钮移至副手上方。只调整既有槽坐标，不替换 ResultSlot/玩家库存。废除 44px 装备侧栏及其宽度补偿注入。
- 生存/冒险提供增强；创造/旁观不请求菜单、不添加按钮、不预取状态、不响应 C，服务端也拒绝相关请求。临时菜单切入禁止模式时在下一游戏 tick 关闭并安全返还网格/光标；创造回到原版目录，旁观回到原版 HUD。返回生存/冒险不自动打开/升级，须下一次正常打开背包。
- 增强同样覆盖原版实体工作台的 CraftingScreen；已打开且 stillValid 的工作台自身提供九宫格能力。Tooltip 合并为“不可合成：原因”，可合成只显示状态；状态角标深度高于物品、低于 Tooltip。
- M3 仍只支持一次普通合成（产量遵循配方），最大数量执行与计划解释一起放在 M4，避免扩大 M2 事务协议。
- 连续切换分类的索引越界作为 M3 阻断项：状态与 C 不读取动画索引；按钮重绑定、绘制、Tooltip、旁白和原版选中读取校验当前列表。

## 1. 唯一目标

让原版背包配方书成为完整、自洽的 Craftable 操作入口：玩家无需逐个悬停即可看到当前工作环境下的配方状态，`showing craftable`、按钮、Tooltip 与 `C` 使用同一权威状态；附近有工作台时，左键预览与手动操作进入真实且安全的 3×3 背包菜单。

M3 只解决选择、显示、状态同步和菜单拓扑，不扩大 M2 服务端“单步普通原版合成”的能力。

## 2. 范围预算

### 2.1 必须完成

- 从客户端已同步的配方目录建立 Craftable 显示视图，不批量解锁配方；
- 仅为当前可见页和悬停候选取得服务端状态，打开页面、翻页、搜索和分类变化时主动预取；
- 同一环境世代内合并请求、限制批量大小与刷新频率；
- `CRAFTABLE`、`PARTIAL`、`BLOCKED` 进入同一客户端状态模型；M3 可展示 `PARTIAL`，但真正产生部分计划仍由 M4 实现；
- `showing craftable`、分类可见性、按钮样式、Tooltip 和 `C` 使用同一状态投影；
- 制作响应只失效受影响状态，并提供明确的待确认过渡，不把“尚未刷新”显示成 `BLOCKED`；
- 附近工作台时使用客户端/服务端同构的实体 3×3 背包菜单，覆盖放置虚影、结果槽、普通点击与 Shift 点击；
- 工作台失效、重生、切维度、切换游戏模式和断线时安全刷新或关闭菜单；
- 自动测试、客户端冒烟测试、专用服务器基线和人工复测清单。

### 2.2 明确不做

- 递归合成、部分完成执行或缺口求解（M4）；
- 熔炉、高炉、烟熏炉或无等待处理（M5）；
- JEI、第三方工作站和第三方容器兼容；
- `Z` 撤销、事务历史或持久状态；
- 复制整份 `InventoryScreen`、`RecipeBookComponent` 或替换 `Player` 的库存对象；
- 每 tick 扫描全部配方或向客户端同步附近容器内容。

任何子任务需要上述能力时必须停止在结构化“不支持”或显示降级，不得建立未来通用框架。

## 3. 固定架构边界

M3 只允许新增三个职责清晰的客户端概念和一个菜单边界：

1. **目录投影**：回答哪些已同步配方允许在 Craftable 的 `ALL` 视图出现；
2. **状态协调器**：对可见目标去重、分批请求、按世代合并响应并管理待确认状态；
3. **配方书投影**：把统一状态映射到原版集合、筛选、按钮和操作；
4. **3×3 菜单契约**：服务端拥有槽位与有效性，客户端只镜像相同拓扑。

不得新增通用 UI 框架、事件总线、前端插件 SPI、工作站抽象层或第二套配方模型。`DirectCraftingService` 仍是 `C` 键唯一执行门面，M2 事务类不引用任何客户端或菜单类。

## 4. 分步实施与停线门槛

### M3.0 原版内部取证与契约测试

- 固定 `RecipeBookComponent`、`RecipeBookPage`、`RecipeCollection`、`RecipeButton` 和 `InventoryMenu` 的 1.21.1 调用关系；
- 找出可见按钮列表、搜索/分页刷新点、过滤判据和菜单重建的最窄注入点；
- 为目录策略、状态生命周期和 3×3 槽位表先建立纯逻辑测试；
- 决定菜单注册、打开与失效重开协议，并形成 ADR。

停线门槛：若必须复制整个原版屏幕或替换 `Player.inventory` 才能继续，应停止实现并重新评估方案。

### M3.1 可见页状态协调器

- 页面可见后主动收集按钮内候选配方，不依赖悬停；
- 使用有界批次载荷请求同一环境世代的状态，服务端仍逐个独立验证目标 ID；
- 状态至少区分 `KNOWN`、`PENDING` 和 `UNKNOWN` 生命周期；业务结果仍为三态；
- 成功创建后进行定向失效和立即刷新，旧状态只能显示为待确认，不能回退成伪 `BLOCKED`；
- 离开世界、数据包重载、翻页和搜索变化时清理或替换正确的请求世代。

验收：打开配方页后不移动鼠标，当前页状态会在有界时间内出现；制作后没有短时错误红框；快速翻页不会产生请求风暴或接受过期响应。

### M3.2 目录、集合与筛选统一

- 从客户端配方管理器构造 Craftable 可见目录，显示策略与原版解锁进度分离；
- 将统一状态投影到 `RecipeCollection` 的可制作集合语义；
- `showing all`、`showing craftable`、分类、搜索、按钮、Tooltip 和 `C` 共用同一判据；
- 多配方同产物按集合最佳状态显示，保持 M2 已验收的稳定目标选择；
- 样式不得形成原版红框外叠加绿框的双重真值。

验收：箱中材料可用但背包无材料时，条目无需悬停即进入可制作筛选；无工作台时 `ALL` 仍可显示钻石镐并解释缺少工作站；不改变 `/recipe` 解锁记录。

### M3.3 实体 3×3 背包菜单

- 定义稳定槽位编号和客户端/服务端共享拓扑；
- 保留玩家原有 36 格背包、护甲、副手及原版交互，不替换库存对象；
- 工作台能力存在时开启 3×3，失效时安全迁移或返还网格物品并恢复 2×2；
- 原版左键配方放置、虚影、结果槽、拿取与 Shift 点击使用真实 3×3 槽；
- 服务端拒绝客户端伪造的工作台能力或越界槽位操作。

验收：钻石镐虚影与材料落入正确九宫格；生存/冒险及切入创造/旁观、死亡、重生、切维度、另一玩家拆工作台和断线重连均不复制、不吞物、不出现幽灵槽。

### M3.4 原版式收尾

- 完成三态颜色之外的形状/图标或文字区分，保证无障碍可辨识；
- 普通成功保持静默，主动失败继续使用可合并原版 Toast；
- 配置直达入口只复用现有配置页，多人环境显示服务端有效规则摘要；
- 完成中英文文本、客户端矩阵、局域网双人复测和性能记录。

## 5. 网络与性能预算

- 客户端只能发送配方 ID、请求序号和当前视图批次标识；不能发送材料、槽位或成功状态；
- 单批只包含当前可见按钮展开后的去重配方 ID，并设置硬上限；
- 服务器按玩家限流，超限可延后或拒绝，不能阻塞主线程；
- 同一环境世代与配方 ID 的结果可复用，过期响应不得覆盖新世代；
- 配方书关闭且没有执行请求时，不持续发送状态包；
- 不发送附近库存明细，只返回状态、结构化原因和环境世代；
- 常见页面首次稳定不得产生可感知卡顿，具体包大小、延迟和扫描耗时在 M3.0 取证后固化为数值门槛。

## 6. 强制测试矩阵

### 6.1 纯逻辑

- 可见候选去重、批次切分和请求优先级；
- 响应乱序、跨世代、超时、页面切换与断线；
- `UNKNOWN/PENDING/KNOWN` 与三态的正交映射；
- 同按钮多配方的稳定聚合；
- 制作后定向失效，不产生伪 `BLOCKED`；
- 2×2/3×3 槽位编号、快速移动目标和物品返还。

### 6.2 GameTest 与运行时

- 工作台放置/拆除与菜单有效性；
- 满背包时关闭或降级菜单的网格物品去向；
- 两名玩家共享环境且一方改变工作台或材料；
- 死亡、重生、切维度和断线；
- 专用服务器不加载客户端类；
- 客户端不同 GUI 缩放、中英文、搜索、翻页和 `showing craftable`。

## 7. 完成条件

- M3.0 至 M3.4 逐段通过，各段失败不能用下一阶段功能掩盖；
- 首次显示无需悬停，成功制作后无错误状态闪烁；
- 配方目录、筛选、视觉、Tooltip 与 `C` 只有一个状态来源；
- 真实 3×3 菜单的所有生命周期测试无复制、吞物、幽灵槽或断线；
- 原版配方解锁进度未被污染；
- 未提前实现 M4/M5/JEI/撤销或第三方兼容；
- 验收报告记录自动测试、性能证据、已知限制与人工复测清单。
