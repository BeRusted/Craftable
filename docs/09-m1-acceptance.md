# M1 验收报告

- 验收日期：2026-09-02
- 环境：Minecraft 1.21.1 / NeoForge 21.1.235 / Java 21
- 结论：**通过**

## 1. 已落地契约

- 使用 NeoForge `ModConfigSpec` 分离注册服务端与客户端配置；
- 服务端扫描范围被限制为水平 1..16、垂直 0..8，预览缓存限制为 0..20 tick；
- `EnvironmentSnapshot` 包含维度、原点、扫描设置、捕获时间、按玩家单调世代、唯一资源端点和唯一工作站端点；
- `EnvironmentSnapshotService` 成为运行时唯一入口：预览可短缓存，创建强制刷新；
- 玩家退出时释放快照和限流状态，重生与切维度时使快照失效；
- 工作站以稳定端点表达玩家固有 2×2 和附近工作台 3×3 能力；
- 原版锁检查不调用带声音/消息副作用的 `BaseContainerBlockEntity.canOpen`；
- 网络协议升级为版本 2，请求只包含配方 ID 与请求序号；响应回显序号，客户端拒绝同配方的旧状态响应；
- `/craftable environment` 只允许管理员或开发环境使用，只显示结构与数量摘要，不显示具体物品身份。

## 2. 防架构偏移检查

- 没有引入 JEI、`IItemHandler`、领地或第三方兼容；
- 没有创建 `compat`、通用动作 SPI、持久化快照或每 tick 扫描器；
- 没有修改玩家库存对象、菜单拓扑或 M3 配方书显示语义；
- `execution` 只通过快照服务取得环境，创建路径没有复用预览缓存；
- 客户端载荷不存在端点、槽位、材料数量或工作站字段。
