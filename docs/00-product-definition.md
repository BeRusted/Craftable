# 产品定义

## 1. 产品定位

Craftable 是“基础操作压缩器”，不是玩法模组，也不是存储模组。

它解决的问题是：玩家明明站在自己的工作区中，身边有工作台、熔炉和若干箱子，却仍要反复开关界面、搬运材料、手动处理中间产物。模组应将这些机械性步骤压缩成一次可理解、可预览、可诊断的操作，同时保留材料、燃料、配方、工作站和权限约束。

核心公式是：

`可执行操作 = 玩家意图 + 当前可用资源 + 当前可用工作站 + 合法配方 + 访问权限`

## 2. 不可破坏的产品原则

### 2.1 玩家中心

工作环境是临时的、以玩家为中心的视图，不是世界中的持久网络。离开范围后，资源和工作站立即不再可用。

### 2.2 手动可达

只有在当前状态下玩家理论上可以合法手动完成的步骤，才可被规划器采用。这里的“可达”同时包含：

- 资源存在且可提取；
- 工作站存在且可使用；
- 玩家满足配方和交互条件；
- 没有越过锁、领地保护、所有权或其他模组的权限；
- 所在区块已加载。

仅仅发现了一个实现 `IItemHandler` 的对象，不代表玩家拥有读取或提取权限。

### 2.3 等价消耗

便利不等于免费。每个成功动作都必须完整结算：

- 输入材料；
- 容器物品与配方剩余物，例如空桶；
- 工具耐久或催化剂；
- 熔炼燃料；
- 输出、副产物和经验；
- 工作站自身被适配器声明的状态变化。

### 2.4 服务端权威

客户端只表达“我想制作什么、制作多少、是否接受部分完成”。服务端必须独立发现环境、求解、模拟、复验和提交。任何客户端传来的槽位、材料数量或成功结果都不可信。

### 2.5 可解释

失败不能只显示“材料不足”。至少要区分：

- 缺少哪些基础材料及数量；
- 缺少哪种工作站；
- 有材料但不可访问；
- 存在配方，但搜索预算、循环或兼容限制阻止了执行；
- 输出无处放置；
- 环境在确认后发生变化。

### 2.6 保守兼容

对语义已知的原版设施和显式适配的模组设施执行自动操作；对未知机器只展示“不支持的工作站”，绝不根据方块名、菜单外观或配方类型猜测并消耗资源。

## 3. 工作环境模型

一次环境快照包含三类对象：

1. **资源端点**：玩家背包、附近物品容器、玩家自己的末影箱库存，后续可包含可拾取的掉落物。
2. **工作站能力**：3×3 合成、熔炼、高炉、烟熏炉，以及第三方适配器声明的能力。
3. **动作提供者**：后续阶段的村民交易、剪羊等世界交互。它们不是普通配方，必须有独立的前置条件和副作用模型。

资源优先级默认为：玩家背包 → 玩家末影箱 → 普通附近容器 → 实体容器 → 掉落物。优先级可配置，但同一次计划中必须保持稳定。

### 3.1 初始可用性规则

- 只扫描已加载区块，不因一次合成请求加载新区块。
- 玩家背包始终属于环境。
- 末影箱方块只充当访问玩家个人末影库存的工作站钥匙；不会暴露其他玩家的数据。
- 普通容器必须能从某个合法面提取物品；双箱作为一个逻辑端点处理，避免重复计数。
- 未生成战利品的容器不得被静默探测或提前揭示内容。
- 第一阶段不递归扫描容器物品内部的背包、盒子或便携存储。
- 正在被移除、区块正在卸载或能力已失效的端点不参与提交。

## 4. 第一阶段用户体验

### 4.1 背包内的 3×3 能力

附近存在可用工作台时，背包界面提供 3×3 合成能力。第一阶段先采用“嵌入背包界面的虚拟 3×3 工作区”，由服务端直接执行选定配方；不贸然替换原版 `InventoryMenu` 的槽位拓扑。可行性原型通过后，再决定是否允许完整的手工摆放体验。

这样能避免与饰品栏、扩展背包、配方书和其他修改背包界面的模组发生大面积冲突，同时仍满足“无需打开工作台”。

### 4.2 直接选择目标

第一阶段必须包含最小目标选择器：物品图标网格、文本搜索、配方切换、可制作状态和 `C` 键制作。否则递归合成能力只存在于后端，玩家无法自然地提出“制作钻石镐”这一意图。

完整 JEI 风格的用途/配方百科、收藏、历史、复杂分类和高级搜索可以继续迭代，但不能把“选择任意目标”的入口推迟到第二阶段末尾。

### 4.3 递归合成

示例：附近有工作台，箱中有原木和钻石。玩家选择钻石镐后，系统可自动执行原木 → 木板 → 木棍 → 钻石镐，并把最终产物送入玩家背包。

当钻石不足时，系统可以准备当前目标确实需要且数量受限的中间产物，例如正好两根木棍，并明确提示钻石缺口。不得为了“尽可能合成”而把所有原木都不可逆地转成木棍。

### 4.4 无等待熔炼

附近有可用熔炉、原矿和燃料时，规划器可把熔炼作为配方链中的一步立即结算，并授予对应经验。

这项功能改变了原版的时间成本、并发产能、熔炉燃烧余量和经验球行为，严格说不是纯界面便利。产品将它定义为“允许但可关闭的时间压缩”：

- 默认启用，以符合核心体验；服务端可为平衡或整合包规则关闭；
- 服务端拥有最终开关和批量上限；
- 关闭后仍可规划合成，但会提示需要等待工作站处理；
- 不把燃烧余量凭空跨交易保存，除非以后引入明确的虚拟热量账本。

## 5. 两阶段范围

### 第一阶段：可信且可用的核心

- 玩家背包和附近通用物品容器；
- 工作台、熔炉、高炉、烟熏炉等已知原版工作站；
- 最小目标选择器和背包内操作入口；
- 单步与递归合成；
- 有界的部分完成与结构化失败诊断；
- 燃料、剩余物、副产物、经验和输出容量结算；
- 服务端补偿式事务、多人竞争保护和基础审计日志；
- 配置界面；
- JEI 存在时的早期兼容验证，以及稳定版前的 `C` 键接入；
- 工作站适配器 API 骨架，但不承诺自动支持所有模组机器。

### 第二阶段：更聪明、更广的工作环境

- 完整内置配方浏览体验；
- 更优的可逆路径、替代材料和燃料优化；
- `Z` 键安全撤销；
- 掉落物、实体库存；
- 可达性、视线和可使用性检测；
- 村民交易、生物互动等动作提供者；
- 第三方工作站适配器与兼容包；
- 更复杂的资源类型，例如流体或能量，仅在明确需求出现后评估。

## 6. 明确不做

- 不增加网络控制器、终端、线缆、磁盘或新工作站方块；
- 不自动加载区块；
- 不远程跨维度取物；
- 不绕过锁、领地或所有权；
- 不在第一阶段操控任意未知模组机器；
- 不保证找到数学意义上的全局最优合成方案；规划必须受时间和状态数预算限制；
- 不在客户端直接修改物品或经验；
- 不将“撤销”实现成免费复制或无条件返还材料。

## 7. 成功标准

第一阶段可发布版本至少满足：

- 单人与专用服务器行为一致；
- 钻石镐与铁镐示例均可端到端完成；
- 两名玩家竞争同一箱子最后一份材料时，不复制、不负数、不吞物；
- 配方循环、标签替代、容器剩余物和满背包均有确定结果；
- 没有 JEI 时可独立选择并制作目标，有 JEI 时不显示重复的主浏览器；
- 常见半径下不会每 tick 全量扫描方块或造成可感知卡顿；
- 每次失败都能给出玩家可行动的原因。
