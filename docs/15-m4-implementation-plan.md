## 1. 代码取证与迁移约束

M4 开始时取证的原实现为 `DirectCraftingService`、`DirectCraftingPlanner`、`DirectCraftingPlan`、`DirectCraftingTransaction`、`RecipeBookStatusHandler` 和 M3 契约，避免凭空设计另一套系统：

| 现有职责 | M4 演进 | 禁止事项 |
|---|---|---|
| `EnvironmentSnapshotService` / M1 端点 | 沿用扫描与鲜度，规划开始复制只读资源视图；当前玩家网格/光标补为输入端点 | 不扩展世界扫描范围、IItemHandler、实体或持久网络 |
| `DirectCraftingService` | 最终演进为唯一合成服务门面，接受数量/策略 | 不让网络层分别调用规划器和提交器 |
| `DirectCraftingPlanner.allocate` | 提取实际网格构造/匹配验证，纳入带回溯账本 | 不保留两套不同保护/Ingredient 匹配语义 |
| `DirectCraftingPlan` | 演进为步骤列表计划；单步为长度 1 | 不给单步记录堆大量可空燃料、撤销、机器字段 |
| `DirectCraftingTransaction` | 扩展整链净提取/交付、备份恢复、逐步通知 | 禁止循环调用旧 createOne 分次提交 |
| M3 状态协调器、投影与菜单 | 复用生命周期/限流，补 PARTIAL/搜索限制/物品链页/显式双击意图 | 不复制配方书、创建第二个状态库或修改槽位 |

迁移可短暂保留旧类名适配入口，但只有一个生效实现；M4.6 前删除不再使用的适配层。玩家网格、装备、副手和鼠标的原版交互/关闭返还契约保留；M4 验收修订将当前网格及光标纳入原资源端点作为输入，结果格、装备/副手仍排除，容量只看主背包，见规格 3.2/6.1。不得为此另建求解、库存或事务系统。

## 2. 必要的新职责与体量预算

只在对应阶段确实需要时建立：

1. `recipe/`：受支持普通配方索引与单步实际输入验证；索引绑定重载世代。
2. `planner/`：需求求解、可回退资源账本、预算、结构化结果。资源与计划的内部记录可嵌套，不按每个名词建一个包。
3. `execution/`：沿用并演进现有唯一事务，不新建通用动作执行器注册表。
4. `client/` 与 `network/`：物品链页、数量/配方选择/确认载荷；服务端短期状态只保存意图、关联结果与摘要。

初始审查预算：recipe/planner 新生产顶层类合计不超过 8 个；客户端新增主控组件最多一个物品链页，允许一个独立链布局/绘制控件及一个配方选择弹层；不建设通用图编辑器。只允许一个小型交互会话存储，承载双击关联和详情确认。超过预算不是硬挤成巨类的理由，必须先说明新职责与替代方案、更新计划后再加。测试夹具不计入该预算。

禁止提前建设：公共 SPI、工作站动作插件体系、抽象资源流体/能量模型、通用图数据库、DAG 序列化引擎、持久任务管理器、撤销日志、物品价值打分库。M5 将来确有需求再演进。

2026-09-12 体量预算修订：M4.7 允许 recipe/planner 顶层生产类合计最多 9 个（现有 8 个 + 一个 `RecipeKnowledgeCache` 文件边界类）。共享需求/邻接仍归原 Index；单独分离 I/O 是为了不把索引堆成巨类，不授权额外图引擎、历史存储或空 SPI。可重建静态关系文件不等于被禁止的可执行 DAG 序列化/持久任务。详见 [ADR-0007](adr/0007-shared-recipe-knowledge.md)。

## 3. 分步实施与门禁

### M4.0 契约夹具与性能取证

先做：

- 固定原版示例实际配方输入/产量/剩余物，包含木棍、钻石镐、铁粒转换、蛋糕空桶。
- 建立精确组件账本、单步/多步计划预期的测试夹具；测定旧直接路径作为对照。
- 只在开发测试中测量 M3 `~` 延迟各段，保留配置翻译缺失维护项，不借机重构整个前端。
- 验证标签枚举、规则与重载事件、物品链层对菜单的影响、通知次数及净交付容量模型。
- 取证原版玩家丢物与实体创建事件、取消/失败返回、拾取延迟、同 tick 清理的安全性；确认余料溢出输出可以守恒实现。
- 输入夹具先复现长按、双击、高 RTT、第一击成功后第二击材料不足，固定完整/部分意图区分。
- 对规格第 8 节初始上限测量：普通/深链/分支/循环图，1/16/64 容器，单/双玩家；分离扫描、复制、求解、提交、通知和网络等待。

门禁：给出预算取证记录与不支持配方判定测试；若必须跨 tick 才安全，先修订 ADR，不能默默把实时世界访问搬到工作线程。此阶段不得提供一个会消耗资源的半成品递归入口。

### M4.1 普通配方索引与只读完整规划

- 在重载后按需构建确定索引，不按玩家/每帧全量重建；生命周期测试先于缓存优化。
- 实现固定 1 次根目标的只读需求回溯，现物/标签分配、实际网格、批量余量与剩余物。
- 加入循环剪枝、完整预算传播、每次请求的精确状态记忆化。
- 输出整链计划或诊断，但尚不提交；不把缺口和预算耗尽混为一类。

门禁：完整钻石镐和有起始资源的存储转换计划正确；稀缺材料竞争能回溯；特殊/锁定/受保护/不支持配方有明确结果；原始容器零写入；随机小图测试终止且不重复承诺资源。

### M4.2 整链容量与唯一事务

- 先统一长度 1 与多步的计划/备份/插入路径，迁移所有入口，保持单步测试。
- 实现有界中间托管及最终净交付容量模拟；不要求每个内部步骤占实际背包格。默认严格模式必须装下所有余量。
- 整链一次提交，提交前完整复验、原版端点失败恢复、逐步提交后通知。
- 为每个提取/插入阶段注入故障，为通知加入重入/异常防护测试。

门禁：单步与原 M2 结果一致（受保护材料这一显式调整除外）；多步中途故障恢复完整提交前像；最终成品和中间步骤事件次数正确；未完成此门禁不进入部分完成，防止把事务漏洞包装为功能。

### M4.2b 余料溢出输出（事务门禁，不是纯 UI 设置）

- 增加世界 REQUIRE_SPACE/DROP_OVERFLOW 与客户端只收紧偏好，默认不掉落；主产物、前沿交付、余料按来源精确分类。
- 插入主产物后尽量容纳余料，剩余按原版丢弃表现生成；同组件合并且有实体数量硬上限。
- 实体创建纳入同次提交，记录精确对象；失败先安全清理本次实体再恢复库存，不搜索删除附近其他掉落物。
- 任意生成阶段失败/取消、部分堆叠、最后一个实体失败、多人拾取边界建立故障测试。不能证明受支持原版路径安全时不得启用设置，不用持久补偿队列兜底。

门禁：只有一个结果槽容量时原木+钻石能得到镐并掉准确余料；镐也装不下时零变更；关闭掉落恢复严格规则；实体/库存守恒全部通过。此功能不包含地面物品输入扫描。

### M4.3 固定数量和显式部分计划

- 固定 1..上限批次，每个实际步骤仍完整结算；动作预算包含全部中间步骤。
- 区分部分根目标与准备材料；完整候选查找优先，预算/候选截断禁止自动部分执行。
- 先实现安全前沿白名单与现物需求抵扣，再接 EXPLICIT_SAFE；单击 FULL_ONLY 失败不消耗，双击或详情明确点击已显示的部分方案“合成”才申请部分完成，服务端与客户端策略取更严格者。
- 双击处理独立按下/释放、目标/菜单配对、第一份请求结果关联；不等待双击窗口拖慢完整制作，也不把长按或第一击成功后第二击失败变成部分意图。
- 同一环境下连续 C 的前沿重复准备测试必须先通过；保护材料不因从单步进入递归而失效。

门禁：规格第 5.3 节数量矩阵通过；零钻石不动钻石分支、重复 C 不加工多余原木、NEVER 零变化、CONFIRM 未确认零变化；无工作台和预算耗尽不得自动准备。

### M4.4 集中求解与预览效率门禁

- 用开发夹具提供节点配方约束/数量意图，先完善有界 MAX 和混合中间路线，不依赖图页调试算法。
- MAX 复用同一个求解器和总预算，不启用“每个 N 各跑一次完整最大预算”，也不能把多个独立路径的最大值相加重复承诺库存。
- 将单步快路径、按输出索引、失败状态记忆、可见页/详情/MAX 优先级、公平预算、退避和正确失效集中对照测量。
- 记录已证明最大值与已知可行下界，不能因候选截断、容量非单调而给出虚假 MAX。
- 分解 M3 2 秒收敛问题；必要的临时主线程只读搜索分片需基准证明并修订 ADR，不启动世界访问线程池或持久任务系统。

门禁：相同夹具下计划正确性不因优化变化；普通可见页/详情目标 P95 500 ms（环境/RTT 和 M4.0 校准值必须记录）；MAX 不阻塞 C，持续双玩家查询无无限队列，报告耗时分位数、最大值及截断/有效回答率。未通过时先缩小复杂查询范围/优化瓶颈，不把问题推给图页。

### M4.5a 可编辑物品链页、滑槽和确认

- Shift+C 打开当前菜单内图页：左上可用工作站图标、右侧目标/向左依赖、下方数量滑槽和单一“合成”；部分前沿直接在图上显示，实际混合原料拆并列分支，额外材料标无阴影 `!`。复用现有授权/资源版本自动更新，图右下角小刷新在查询期间旋转/禁用；原版字体、控件与旁白，平移折叠适应窄屏。交互契约见 16 文档第 3 节，不另建同步或执行机制。
- 完整计划和不可执行的解释路线分开显示，缺口/不支持/预算未确定如实标注；已有中间物可折叠，不强制制造。缺料解释在原投影内先分配现物、复用选定生产配方的假设余量，只对不足部分增加整批输入，不将独立取整数相加；不伪造操作/成本或授权。
- 先解析共享来源，再以唯一的同父等价规则合并需求及子树，精确材料/组件、配方、状态与依赖结构一致才汇总；保留所有原路径，点击约束全部代表需求。截断 OR 叶只在同份冻结目录提供完整候选证据时合并，保留实际木材/状态差异，超限无证据仍分开。不同父节点的需求分开，上游共享材料只计一次。图控件只保留一个有限整理入口，统一定位和正交通道路由：有界尝试同父换序、单输入链对齐及同来源/同精确物品组件/同唯一配方需求的同列相邻，不改变依赖深度、数量或点击。多输入产物固定一个入点，共用来源一个出点；节点遮挡及无关共线假接优先消除，剩余正交交叉用断口区分，局部通道优先于外围兜底；原始连接和绘制段布局时缓存，不逐帧寻路。界限见 16 文档 3.2，C.22–C.23 替代 C.21 的单次软对齐限制，不保留两套整理机制。默认解释复用现有精确逆配方判定防止往返，不删除显式选择或真实转换。节点收支按物品/组件汇总，隐藏注册 ID；连线统一描边/白芯两遍绘制，小刷新为开口圆弧箭头。不改变计划身份、求解器、账本或事务，回归仍从 planning 入口运行。
- 点击节点挑选配方，允许查看不可用候选；选中后重算整份资源分配。用户明确选择为约束，可恢复自动；失效节点选择不能套到新支路。
- 滑槽默认 1 次、显示产物件数；最大值 0/未知/受上限限制分别处理。混合路线/MAX 改链出现 !，执行前更新路线与净消耗并确认，不静默突破手动约束。
- 服务端令牌玩家绑定、一次性、限时、世代/菜单失效；确认复验新鲜资源并比较已见摘要，含余料掉落与节点约束。M4.9 完整见证验证不重新搜索；部分及显式回退沿用服务端规划，不直接执行旧计划。
- 协议统一升级；详情数据按需限长。M4.8 后本地状态不再走旧被动状态包；拖动去抖、修订号丢弃过期结果；图布局与绘制性能独立测量。

门禁：重复/过期/跨玩家令牌零变更；路线/实际消耗改变后重确认；输入焦点、Esc、换模式不丢网格；共享材料不重复计数；不同缩放/深链/旁白可用；缺失工作台和未接入熔炉不误标绿勾。

### M4.5b 原版配方书状态接入和性能回归

- 被动按钮按固定 1 次求解；CRAFTABLE/PARTIAL/限制原因和未知生命周期统一，不拆第二套状态。
- 保持图标轮播与 C 目标独立、同状态不重建、仅可合成不包含只能准备材料的目标。
- 初期曾复用每批 32 个 ID/单在途的服务端查询；该路径已在 M4.8 退役，现行规则是授权快照内本地续算、完整/诊断分额和 3:1 隐藏保底，不恢复旧轮询。
- 记录单次/多次/策略缓存身份和重载清理；不能使用旧 MAX 成功给 C 染绿。
- 处理已登记的配置分类中英文文案缺失，实际打开页面验证，不开发新配置框架。

门禁：旧 M3 连切目录压力与虚影/模式回归保留；同环境与 M3 对照不出现持续重建、显著延迟退化或新增掉帧。超预算不得假报材料不足，也不能无休止显示无解释的 `~`。

### M4.6 集成验收与清理

- 完整执行原 JUnit/GameTest 和新增覆盖；开发客户端脚本验证递归/部分状态/详情与旧模式边界。
- 清理临时迁移层、重复模型、未使用的未来字段和 TODO 骨架；仅保留现阶段实际使用的包。
- 发布独立 M4 验收报告：自动结果、版本/JAR/协议、预算测量、已知保守限制、人工复测清单。
- 用户完成单人/局域网复测后才宣布 M4 关闭；专服至少启动及事务回归，客户端代码不得加载到服务端。

收口整理顺序（M4.7–M4.9 交付后执行）：

1. 独立记录清理前/后基线，只删除有证据的退役入口、编解码和自测；不改求解器/账本/事务。
2. 当前规范、进展、验收与历史取证分离；历史失败不丢失。
3. 测试集中入口和覆盖分类，夹具按职责保留源集；大型客户端场景拆为由少量入口驱动的模块，断言/样本/顺序不变。
4. 运行分组回归并补人工清单；自动通过不等于 M4 人工关闭。

### M4.7 增补门禁与实施顺序

在最终人工验收之前，按 [共享配方知识设计第 7–8 节](19-m4-recipe-knowledge.md#7-m4-是否现在做结论与顺序) 执行：a 分阶段性能取证与键/指纹验证 → b 原索引共享关系 → c 有界磁盘缓存 → d 自动回归、新交付物与 A–I 人工复测。M4.7 是 M4.6 开发交付后的收口增补，不意味着 M4 已关闭。

要求每步独立可测：知识构建不随移动/重复目标重做；资源分配仍实时且可回溯；重启复用、配方/标签重载、缓存损坏/超限/写入失败安全降级；候选缺失不冒充无解。比较构建/查图、动态闭包、账本搜索与 MAX 成本，不以“已缓存”代替性能证据。历史成功方案不进入本阶段。

### M4.8 版本化筛选与同核心客户端浏览

按客户端规划设计第 7 节依次完成：基线/授权契约 → 同版本闭包及 FULL_ONLY 证据 → 不可变输入/原位续算 → 客户端快照/队列/详情/MAX。旧全范围轮询退役，不双算；同资源身份累计预算耗尽不重置。传输期限、2 ms 共享调度与 3:1 隐藏保底按设计第 4–5 节，不另建框架。

### M4.9 完整见证与阶段收口

服务端验证完整固定量见证，不重搜替代路线；部分及首次失败关联仍由服务端证明。单独验证正常/拒绝成本、安全反例、差分和事务，不能借 M4.8 浏览收益替代。原版普通体验、安全和正确性是关闭门禁，低配/大目录/多人高 RTT 扩展矩阵留待 M8。

## 5. 人工复测范围

1. 空背包、工作台、箱中 1 原木+3 钻石：不悬停即绿，C 获得镐和准确余量；左键仍只用随身材料。
2. 缺 3/1 钻石：部分图标与缺口正确，单击不消耗、双击只加工一次木材；重复双击不多做；补钻石后一键完成。
3. NEVER/CONFIRM/EXPLICIT_SAFE 与远程服务端规则：客户端不能放宽规则；确认材料变化后不偷偷改用其他材料。
4. 固定多批次及 MAX：次数/件数/上限清楚，不盲目清空所有资源；容量/预算不足区别清晰。
5. 铁粒转换、复杂标签、带名材料、空桶、满背包和余料策略：严格模式拒绝，允许溢出时主产物入包、仅余料掉落；生成失败不吞物/复制。
6. 两机争用、换模式/拆台/断线/重载、重复确认：整链失败不留下半成品、无吞物复制。
7. 连切目录、仅可合成、详情开关、不同 GUI 缩放和语言：无旧索引崩溃；测稳定时间、双方日志与服务端延迟。

## 6. 关键代码注释要求

实现时必须在以下位置解释“为什么”，不能只复述代码：

- 配方批次为何不能按目标件数拆分，以及多余产物归属；
- 分支账本的所有权/回退、组件键与循环剪枝的完整状态；
- 为何预算未证明时不能自动部分完成；
- 为什么整链一次提交、提交后通知异常不回滚；
- 中间托管为何不要求每步实际背包格、为何只允许本次同步事务存在；
- 余料与主产物的来源分类、实体创建失败清理顺序及仅清理本次对象；
- 双击关联第一次完整尝试，长按和“首次成功后第二次失败”不得退成部分操作；
- 物品链是计划展示投影，节点换配方为何要全局重算、MAX 不能默默覆盖手动约束；
- 确认令牌不授权执行旧计划，摘要比较和一次消费顺序；
- 默认按钮与详情数量/策略缓存的隔离；
- 主线程/只读快照边界、时间预算仅为软上限。
- M4.7：静态知识与当前资源状态的所有权区别、Ingredient 键等价性、未缓存与完整空结果区别、磁盘指纹/重载失效、原子写入与过期世代保护、超限回到原索引而不是截断配方。

## 7. 实施前默认决策与变更控制

已按玩家反馈修订并接入的交互：单击 C 只尝试完整一次，失败后同目标双击表达部分意图；默认 EXPLICIT_SAFE；Shift+C 打开可编辑物品链页和数量滑槽；可选溢出余料掉落，默认严格收纳。只准备中间物的 PARTIAL 不进入“仅可合成”；默认保护非默认组件材料；MAX 改链必须提示并展示实际方案。MAX 整次分片上限与保守未知的实测限制见交互契约和验收报告。

这些是本次建议的设计基线，用户可在实现前调整。预算数值、实体输出恢复和可编辑图页生命周期由 M4.0 验证，集中效率由 M4.4 检验；若验证推翻设计，先更新规格/ADR，明确影响与替代方案，不靠越界实现“勉强通过”。该条原为细化阶段边界；用户现已授权按计划实施 M4。完成集成、自动验证与人工清单后再交付，不把实现中状态视为已验收。
