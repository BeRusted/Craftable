## 1. 执行顺序与范围

PR #2 的四项后续分别落到以下阶段。文档和设置先于 M5，配方书呈现留到 M6，新增资源端点留在第二阶段。

## 2. P2：原生配方书呈现合同（M6 实施）

- 分类复用原版配方书入口。自定义分类、搜索、收藏与筛选只影响显示范围，不授予配方解锁，也不改变服务端配方合法性。
- 配方收藏是玩家个人的浏览偏好，不是 M8 的材料锁定、材料保留或路线黑名单；不能在本轮引入求解成本策略。
- 创造目录只提供分类/顺序映射。一个物品出现在多个标签时必须有稳定归属及去重规则，目录缺项或数据重载时有明确原版回退；不因此在创造/旁观模式启用 Craftable 制作能力。
- 同成品且精确组件相同的替代配方可在该组内择优；不同材质或组件的成品必须尊重当前展示/选中的输出。Shift+C 的最终成品变体与递归原料选择分开，切换后重新计算整链与消耗。
- 按钮输出轮播与合成格材料虚影轮播是不同生命周期。显示图标、颜色、Tooltip、旁白与 C 的目标必须一致；不得恢复“轮播显示桦木船而制作橡木船”的旧行为。
- 原版分类、搜索、收藏或排序策略改变时重建相应显示作用域；仅资源刷新时保留上一已知列表、页码与位置，不按瞬时可行性重新排序，不先清成未知再闪回。
- 教学维持简洁、可发现：普通配方 Tooltip 的键提示简短，进阶手势由键位/玩家指南说明。不新增常驻教学 Toast、首次进世界提示或独立主浏览器。

M6 验收至少覆盖分类/搜索/筛选/收藏组合、重复标签及目录回退、数据重载后稳定排序、同成品替代/不同材质输出、槽位虚影与连续 C。实现时沿现 `RecipeBookProjection`、`RecipeButtonTargetResolver` 和窄 Mixin，不复制整份原版页面；M11 仍只负责后续第三方/非标准条目映射。

## 3. P3：R1 存储资源端点设计（第二阶段实施）

R1 与 M9 分开：R1 解决“已有存储内容怎样授权、定位及写回”，M9 解决“玩家周围哪些方块/实体在检测范围内”。实现可拆为 R1a/R1b；先后关系不要求提前实现可达性搜索、实体输入或第三方能力。

### 3.1 R1a：末影箱物品作为个人库存钥匙

用户确认的新增规则是：玩家持有末影箱方块物品，或当前已授权工作环境中有该物品，即可访问该玩家自己的末影库存。它不要求找到远处已放置的末影箱，也不授权全世界扫描。

- 当前基线仍是附近已放置且可用的末影箱准入。R1a 将物品钥匙规则作为明确增补，保留现世界总开关及既有可用方块入口。
- 主背包、当前网格/光标、已授权附近容器中的钥匙均按实际内容检查；副手持有可单独作为钥匙资格，不因此把所有装备/副手纳入可消耗原料。
- 钥匙只授权本人的 `PlayerEnderChestContainer`；不暴露其他玩家内容，不消耗钥匙来“购买”权限，不把钥匙数量变成多个末影端点。
- 基础来源必须先完成权限/锁/距离/区块/菜单验证，再检查其中钥匙。未授权末影库存里的钥匙不能让该库存自授权；不得循环遍历直到取得原本不可访问的资源。
- 同一玩家的多个物品钥匙和可用方块只映射一个末影端点。每次新鲜检查重新证明资格，钥匙移出授权环境、权限失效或菜单结束后不能复用旧授权。
- 若计划会消耗最后一个钥匙本身，不能一边把它作为普通原料一边假定资格永久有效。实施须明确事务内资格与钥匙排他规则，覆盖预审后钥匙移动及确认时撤权。
- R1b 以后如允许便携内容里的钥匙，只有已授权且已绑定的载体路径可参与准入；这不改变末影库存禁止自授权的规则。

### 3.2 R1b：潜影盒、收纳袋等便携内容

附近已放置的原版潜影盒当前可按方块容器使用；R1b 新增的是物品载体内部内容，不是重复实现方块潜影盒。

- 资源身份由真实载体根来源、精确组件指纹与内部路径构成。客户端仅收到有界不透明来源引用，不收到可任意写入的路径/活容器句柄。
- 载体在背包、光标、网格或授权容器之间移动时重新绑定实际来源；同一内容不能同时由旧路径、新路径和多个包装视图计入资源。
- 只开放明确支持的原版载体；嵌套深度、载体数、总虚拟槽、输入数、同步字节与临时内存均须先定上限并在扫描/解码/执行处验证。非法嵌套、环、超限或不支持内容保守拒绝，不为目录整齐引入通用递归框架。
- 载体本身与内部内容互斥分配：同一计划不能把整盒作为材料，同时又消耗该盒内物品。默认组件保护不能为扫描内容而整体取消。
- 每个原料只属于一个真实根写集。父/子载体更新按明确顺序组装，主背包容量模拟必须包括更新后的载体，不能被随后发布的旧背包结果覆盖。
- 提交前重新校验根载体、每条内部路径、精确组件、数量与权限；写回使用真实载体组件，不改一份脱离世界的 `ItemStack` 副本冒充提交。
- 失败恢复根载体及所有受影响组件前像；输入、成品、余料与掉落实体继续由唯一事务守恒。故障注入覆盖部分写回、载体移动、父/子冲突和回滚失败边界。

R1a/R1b 的代码、测试和新的公开兼容承诺均不在 Pre-M5。若以后要前移到 M5–M6 之间，需另行确认第一阶段范围变更。

## 4. P4：设置语义与预算合同

### 4.1 整链步数配置

已关闭的 M4 基线是硬性最多 128 次实际配方执行，包含根批次与中间步骤。`crafting.maxCraftBatch` 只限制根配方次数，不能替代整链步数。

当前已注册世界规则 `crafting.maxPlanSteps`：默认 `128`，范围 `1–256`；已进入授权规则、资源身份、客户端/服务端搜索、完整见证复验与最终提交检查。续算和诊断冻结有效值，负搜索证据仅在相同上限复用。计划/见证/投影固定最多表示 256 步，生成物账本另以每步一个产物及最多九个返还物的 `256 × 10` 批次界限保护；独立字节和预算限制不放大。代码实现不等于下列验证已通过，不能将旧 M4 的 128 步验收改成 256 步验收。

- 分开有效世界限制与绝对表示/解码上限；服务端拥有有效值，客户端个人偏好不能放宽它。
- 搜索、步数下界/MAX 上界、计划构造、完整见证复验、显示投影、生成物账本与网络解码使用一致且经过验证的边界。
- 有效步数进入授权规则/内容身份；配置重载使不匹配的证据、MAX、显示见证和排队确认失效。旧客户端/旧帧不能通过更大的本地值绕过限制。
- 不提高时间、状态、前台调度或全服准入预算。较大的可表示计划不等于保证能在现预算内求出；未知仍是未知，不能自动转为部分授权或精确 MAX。
- 64 KiB 动作/完整投影编码等独立上限仍有效。步数可表示但字节/内存超界时必须保守拒绝，不静默删步骤后批准。
- 验证至少覆盖 1/128/256 边界、配置调低/调高后的缓存失效、恶意超限见证、真实大批计划、原 32/42 箱基线、组件/返还物/容量及专服隔离。若协议字段改变，按同 JAR/新协议处理，不宣称旧协议兼容。

P4/P5 历史构建协议为 10；P5a 的新增规则字段使用协议 11，联机两端必须使用同一新 JAR。M4 历史关闭构建仍是协议 9，各批次原验收记录保留，不混用协议或测试身份。

### 4.2 `previewCacheTicks` 旧键修正

`environment.previewCacheTicks` 现已明确为诊断专用旧键：默认 5、范围 0–20，0 禁用缓存，只影响 `/craftable environment`。普通设置页与规则摘要已隐藏该项，高级/Mods 完整配置保留有界兼容值；常规浏览、审阅、执行和确认仍新鲜校验，不控制配方书或 Shift+C 的刷新速度。

- 按诊断专用旧键处理，明确弃用普通“预览缓存”表述，并从普通设置 UI/世界规则摘要移除，不伪装成仍能优化玩法的开关。
- 已有 TOML 的该值可按有界兼容迁移保留给诊断；新增说明必须注明默认值/范围只影响诊断，不影响资源更新和制作安全。
- 不能为让旧设置“看起来生效”而将常规 `fresh` 改成缓存授权；执行和确认始终新鲜校验。
- NeoForge 与 Fabric 的实际注册、重载默认值、展示与命令语义应一致；删除配置 section 时回到默认值，不能悄悄保留上一次运行值。

### 4.3 P5a：服务端直接部分准备规则

该设置只决定：已经明确请求部分准备、已经支持并通过权威验证的实际步骤，是否可省去额外确认。它不禁止正常完整合成，不替代配方支持、安全执行或缺料总策略；“全部需要确认”也不等于“完全禁止部分合成”。单次 C 失败仍不消费材料，`NEVER` 禁止部分执行，`CONFIRM` 始终要求再次确认，个人偏好和世界限制取更严格者。

- 一套服务端不可变 `DirectPreparationPolicy`，使用已注册的 `crafting.directPreparationMode`、`crafting.directPreparationAllowedRecipes`、`crafting.directPreparationConfirmationRecipes`。普通与 NeoForge 专业界面共用这三个定义、默认值、校验及 TOML；没有平行配置真值。
- `CUSTOM` 为默认：沿现 `Entry.safePreparation` 的低风险结构基线，再应用两个具体配方 ID 覆盖表。默认保留原木→四木板、两木板→四木棍/两竹子→一木棍、已识别材料的 9:1 存储转换等数量与输入结构检查。数据包只保留原版 ID，却改为昂贵输入/数量/组件，不能靠 ID 自动进入默认允许集合。
- `ALL_SUPPORTED` 允许所有已支持且通过全部检查的步骤直接部分准备；`REQUIRE_CONFIRMATION` 使所有部分准备都要确认。快捷模式只改模式，不删除自定义名单；切回 `CUSTOM` 后名单恢复作用。两个覆盖表同时含同一 ID 时，“需确认”优先；只在 `CUSTOM` 模式使用覆盖表。
- 保存完整命名空间配方 ID，不按成品物品 ID 整体放行。同成品的不同配方/处理方式分别决定；当前批量选择只影响明确选中的现有配方，不自动授权以后出现的新配方。每表最多 128 项、每个 ID 最多 128 字符，规范化去重排序；合法但未知/不支持的 ID 保留且暂不生效，不能凭配置新增配方或执行器。
- 搜索冻结同一规则值，按实际已执行步骤逐项取合取；只允许第一步或某一产物不足以放行整条准备链。服务端真实见证复验使用同一判断，不相信客户端的 safe 标记。静态目录、配方知识 fingerprint 与跨重启知识缓存不因许可设置改动重建；规则变化只失效对应动态证据、MAX、浏览租约/显示见证和确认。
- 附近来源、权限、解锁、受保护组件、真实 `matches/assemble/getRemainingItems`、物料/余料/贡献与容量核算、唯一事务、原 8 ms 单请求/16 ms tick 和体量限制保持原值。未知、截断、不支持、空间不足不因“全部允许”转为权限；更宽松的许可代表管理员接受材料风险，不构成“所有路线安全”的承诺。

M5 以后炉类只在燃料、耗时、返还物、经验和执行校验完成后接入同一许可判断。此项不提前注册炉类空壳设置、通用处理类型插件或新的配方搜索器。

## 5. P5：原版式设置页面合同

本轮主页调整仍使用原版 `OptionsSubScreen`/`OptionInstance` 控件：六项个人选项直接双列显示，无个人二级页，底部提示说明以上部分个人偏好受当前世界规则影响。控件只改草稿，完成校验并保存已改项，取消/Escape 不保存，默认值只改草稿。标题、Tooltip、默认值、范围和枚举集合复用已注册 `ConfigValue`/元数据，多选策略的共享 Tooltip 每项另起一行，不复制配置定义。普通世界入口在单人、未开放 LAN 且 SERVER 配置已加载时打开八项标量规则和半宽配方名单入口的世界草稿页，不放常驻来源文字或重读按钮；远程/LAN 打开只读页，通过独立限流请求显示当前连接/世界下最近读取的值，footer 中重新读取规则与完成并排半宽，不在规则列表中放来源文字或重读条目。状态、来源与错误保留在重读按钮 Tooltip 和旁白中，pending 时禁止重复读取。未进世界时普通入口禁用，SERVER 未加载时不能编辑；编辑期间上下文变化或开放 LAN 禁止保存，旧连接/世界/序号回复不能覆盖新页面。设置请求不取得库存、浏览租期或制作权限。NeoForge Mods 专业配置保留原生权限，专业 SERVER 配置未加载时同样不能编辑，不提供未来世界模板编辑；普通页隐藏诊断缓存项，专业页返回时已改个人项目保留草稿、未改项目更新，取消普通页不撤销专业页已保存变化。此前七项基础世界页与双列设置验证见 7.4–7.6，P5a 新模式/名单需独立补验；以下合同仍是验收门槛，不把自动结果代作未完成的人工验收。
