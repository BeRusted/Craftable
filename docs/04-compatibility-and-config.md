# 兼容性与配置

## 1. 兼容等级

对外说明应区分四个等级，不能笼统写“支持所有模组容器/机器”。

| 等级 | 含义 | 当前 M4 基线 | 后续范围 |
|---|---|---|---|
| 原生 | 内建语义并进入持续测试 | 主背包/当前网格与光标、获准个人末影库存、可用原版方块容器、普通合成/工作台 | 炉类归 M5；物品钥匙/便携内容归第二阶段 R1 |
| 通用能力 | 通过 NeoForge 标准能力访问 | 不承诺任意第三方处理器已可安全执行 | 第二阶段按所有权/失效/提取契约验证 |
| 显式适配 | 对方或本模组提供专用适配器 | 尚无公开兼容承诺 | 按兼容模块逐个声明 |
| 未知 | 只能发现外观/配方，语义不足 | 不自动执行 | 无完整执行契约仍不自动执行 |

## 2. 第三方容器

NeoForge `Capabilities.ItemHandler.BLOCK`、`ENTITY` 和 `ITEM` 能覆盖大量存储对象，但第一阶段只默认启用方块容器。实体容器和物品内部容器在第二阶段加入，因为它们有移动、递归、所有权和失效问题。

这里的能力契约是后续兼容要求，不代表当前已实现通用能力扫描。第二阶段 R1 单独解决末影箱物品钥匙准入和原版便携载体内容，M9 则解决检测几何/实体；两者不混同。载体身份/内部路径、嵌套上限、直接载体与内容互斥、组件写回及补偿必须先于启用，见 [Pre-M5 资源合同](21-pre-m5-transition.md)。

兼容要求：

- 使用实际侧面查询，遵守 `extractItem(..., simulate)`；
- 处理能力失效；
- 不假定处理器实现 `IItemHandlerModifiable`；
- 不直接改槽位或复制返回的 `ItemStack` 引用；
- 对模拟不纯、返回数量异常或提交不一致的处理器熔断；
- 专用适配器可覆盖通用能力适配器；
- 方块名字相同不等于端点身份相同。

## 3. 权限与领地

能力 API 不负责玩家权限。第二阶段兼容方向是独立 `PermissionProvider` SPI，当前不据此提前注册空接口：

```text
ALLOW     明确允许
DENY      明确拒绝，立即停止
PASS      不知道，交给下一个提供者
```

服务端配置决定所有提供者都 `PASS` 时的默认结果。单人可默认允许，专用服务器建议对非原版或疑似受保护区域默认拒绝。

兼容测试至少覆盖：锁箱、旁观者、冒险模式、领地内非成员、队伍共享容器和玩家离线后的所有权变化。Craftable 不应通过直接能力提取绕过正常方块交互被取消的权限。

## 4. 第三方工作站

没有通用安全方案。兼容模块必须说明：

- 哪类配方可执行；
- 实际输入、输出、副产物与容器剩余物；
- 能量/燃料/热量/催化剂成本；
- 机器是否必须空闲、完整、多方块成型或拥有升级；
- 玩家权限；
- 批量与随机输出；
- 模拟与补偿能力；
- 是否允许时间压缩。

随机输出、概率副产物或会改变世界的大型机器，默认不进入递归规划，除非适配器提供确定的服务端执行契约。

## 5. JEI

### 5.1 依赖方式

- JEI API 使用 `compileOnly`；
- 开发运行时可用 `localRuntime` 测试；
- `neoforge.mods.toml` 将 JEI 声明为可选；
- JEI 类只存在于隔离的兼容包，不能被通用类的签名或静态初始化引用；
- 只使用 JEI 公共 API，不依赖内部 GUI 类。

JEI 集成尚未实现和锁定版本；M11 实施时从官方 Maven/发布页确认实际版本，并用最低/目标两个版本测试，不以旧原型计划作当前兼容承诺。

### 5.2 交互规则

- JEI 与增强后的原版配方书同时保留，任何一方都不替代另一方；
- 两者显示相同的可合成/部分可合成/不可合成状态、环境状态、计划预览和失败原因；
- 鼠标悬停在 JEI 可识别目标上按 `C`：制作一个；
- 批量制作使用可重新绑定的独立操作，避免硬编码组合键；
- 按 `Z`：请求撤销最近可撤销事务，而不是让 JEI 执行反向配方；
- 若 JEI 只提供材料而无法唯一确定配方，打开配方选择或使用服务端首选配方，并在预览中明确显示。

## 6. 原版配方书增强

Craftable 不开发独立的 JEI 风格主浏览器。第一阶段增强原版配方书：

- 保留原版搜索、图标网格、分页、分类、配方切换、提示和叙述；
- 附近有工作台时以有效 3×3 上下文展示配方；
- 显示三态、所需工作站、当前可制作数量和缺口；
- `C` 直接制作；
- 配方选择记忆。

第二阶段将更多第三方配方、村民交易和生物动作接入配方书，并在背包界面加入或兼容更多工作站 UI。原版配方书与 JEI 共享前端桥接和状态模型，但渲染层互不依赖。

原生分类/配方收藏/创造目录映射排序及动画反馈归 M6，而非等待 M11。Pre-M5 先冻结显示身份/稳定页合同：个人收藏不等于 M8 材料锁定，分类不授予解锁，创造目录排序不启用创造制作，不同成品变体不能被同组择优替换。代码与 UI 验收仍在 M6。

## 7. 配置

### 7.1 当前已注册的服务端/世界配置

| 键 | 默认 | 范围/值 | 说明 |
|---|---:|---|---|
| `environment.horizontalRadius` | `8` | 1–16 | 水平检测范围；上限控制立方扫描体积 |
| `environment.verticalRadius` | `4` | 0–8 | 垂直检测范围 |
| `environment.previewCacheTicks` | `5` | 0–20 | 仅供 `/craftable environment` 只读诊断短缓存使用；0 禁用，普通设置页已隐藏，不控制浏览/详情/创建 |
| `environment.includeEnderChest` | `true` | 布尔 | 需附近存在可用末影箱 |

`loadedChunksOnly=true` 是安全不变量，不开放为可关闭配置。当前扫描形状是水平/垂直分别限界的方盒；它不是欧式球体，不应在 UI 中误标为“欧式距离”。M1 没有为尚未实现的功能注册死配置。

当前世界规则（`craftable-server.toml`）如下；Pre-M5 新增有效整链步数及直接部分准备规则，未将历史 M4 的验收改写成新构建通过：

| 键 | 默认 | 说明 |
|---|---|---|
| `crafting.partialExecution` | `EXPLICIT_SAFE` | NEVER/CONFIRM/EXPLICIT_SAFE；只控制显式部分意图，单 C 永不部分消耗 |
| `crafting.surplusDelivery` | `REQUIRE_SPACE` | 可改 DROP_OVERFLOW；主产物必须入包，仅溢出余料可以丢弃 |
| `crafting.maxCraftBatch` | `64` | 1–64 次完整根配方；根与中间实际步骤另受 `maxPlanSteps` 限制 |
| `crafting.maxPlanSteps` | `128` | 1–256 次整链实际配方执行，包含根批次与中间步骤；调高不增大时间、状态或内存预算 |
| `crafting.directPreparationMode` | `CUSTOM` | CUSTOM/ALL_SUPPORTED/REQUIRE_CONFIRMATION；只决定显式部分准备是否省去额外确认，切换不删除两张名单 |
| `crafting.directPreparationAllowedRecipes` | `[]` | CUSTOM 的完整配方 ID 允许覆盖；每表最多 128 项、每项最多 128 字符；空表仍使用结构默认 |
| `crafting.directPreparationConfirmationRecipes` | `[]` | CUSTOM 的需确认覆盖，优先于结构默认及允许表；同样有界 |

`maxPlanSteps` 已接入服务端规则、两端授权快照身份、搜索、完整见证复验及最终提交检查。有效世界上限与固定 256 步表示/解析上限不同；根批次、时间/状态预算、64 KiB 编码和内存边界各自独立。调高步数不保证 MAX 能精确证明或规划必然完成，超预算仍是未知。配置改变使旧动态证据和确认失效；本轮自动回归及第 8 节基础设置用户人工验收已通过，8.1 新名单和后续中文名/UI 复测仍待，见 [验收跟踪](21-pre-m5-transition.md#7-验收跟踪)。

直接部分准备规则不是配方执行白名单，也不禁止正常完整合成。CUSTOM 默认沿当前木材加工、竹子/木棍及精确存储转换的输入/数量/组件结构判断；数据包仅沿用原版配方 ID 不足以成为低风险默认。允许覆盖和需确认覆盖都保存具体配方 ID，而非输出物品 ID；同产物的替代配方分别处理，合法未知 ID 规范化保留但暂不生效，不生成新配方支持。输入需含显式命名空间，表内去重排序；非法列表/超界沿同一注册 spec 校验/校正，不静默截短后授权。

ALL_SUPPORTED 对已支持、通过全部核算的实际准备步骤省去额外确认，REQUIRE_CONFIRMATION 对部分准备一律确认；后者不是完全禁止。CUSTOM 中需确认覆盖优先；快捷模式不清空自定义表。每条链的所有实际执行步骤都须满足许可，搜索冻结与权威见证复验共用同一个不可变策略。单次 C 失败、NEVER/CONFIRM、受保护输入、权限/工作台/解锁、真实配方验证、容量、8 ms/16 ms 与体量限制仍生效，unknown 不得转为执行权限。规则变化使旧动态结果和 token 失效，但不重建静态配方目录/fingerprint 或知识缓存。M5 炉类须完成真实燃料/耗时/返还/经验契约后才接入，不因 ID 被列出而提前支持。

`previewCacheTicks` 保留原键与有界值供诊断兼容；值 0 不复用诊断快照。它已从普通配方书（英文 Craftable）设置页面、世界规则行和扫描摘要移除，高级/Mods 完整配置页仍可查看。常规浏览、审阅、执行和确认始终新鲜校验，不能为让旧设置“生效”而改用陈旧授权。NeoForge 配置缺少 section 或键时恢复注册默认值，数值超出注册范围时钳制到边界（例如 `maxPlanSteps=257` 校正为 256，0 校正为 1）；实际重载回归状态以本轮跟踪为准。

M4 的具体策略和预算以 [行为规格](14-m4-spec.md) 为准。仅已实现的部分完成策略、余料交付规则与已验证的批次上限进入同一配置页；深度/状态/毫秒等首先是开发取证参数，不自动变成允许玩家任意放大的开关。下表不代表现有注册键。

| 键 | 建议默认 | 范围/值 | 说明 |
|---|---:|---|---|
| `enabled` | `true` | 布尔 | 总开关 |
| `detectionMode` | `BOX` | `BOX/EUCLIDEAN/LINE_OF_SIGHT/REACHABLE` | M9 加入；保留当前方盒行为并允许选择欧式距离或可达性 |
| `allowBlockInventories` | `true` | 布尔 | 普通方块容器 |
| `allowEntityInventories` | `false` | 布尔 | M9；运输矿车等实体库存 |
| `allowDroppedItems` | `false` | 布尔 | M9；遵守拾取冷却、所有者和实体竞态 |
| `allowLivingEntityActions` | `false` | 布尔 | M10 实体动作总开关，不代替动作子开关 |
| `allowVillagerTrading` | `false` | 布尔 | M10；只有交易执行器完整时才注册 |
| `allowShearing` | `false` | 布尔 | M10；第一批显式白名单生物互动候选 |
| `recipeVisibility` | `ALL` | `ALL/UNLOCKED_ONLY` | 是否尊重配方书解锁作为显示过滤；不改变服务端配方合法性 |
| `instantProcessing` | `true` | 布尔 | 时间压缩总开关；整合包/公服可关闭 |

键位通过标准 KeyMapping 注册并允许玩家在控制设置中修改：

- `Create One`：默认 `C`，只尝试完整一次；同目标第一次失败后的双击才表达部分意图，详见 [交互契约](16-m4-interaction-and-performance.md)；
- `Plan Details`：M4 使用 Shift+已绑定的 Create One 键（默认 Shift+C），只打开工作站状态与可编辑物品链页，滑槽选择次数/MAX 后确认，不立即批量消耗；没有第二个独立键位绑定；
- `Undo Last Craft`：第二阶段默认 `Z`，M4 不注册未实现能力；
- `Create Max`：M4 不新增直接执行键，通过详情选择；后续独立快捷键另行评估。

`C` 和 `Z` 只在支持的屏幕上下文、存在有效悬停目标或撤销令牌时消费，不能妨碍聊天框和搜索框输入。

## 8. 配置同步与变更

- 世界规则由服务端拥有；客户端界面显示服务端有效值；
- M1.1 使用 NeoForge 内置 `ConfigurationScreen` 提供“模组 → Craftable → 配置”入口；它复用原版 `OptionsSubScreen` 风格、校验、撤销与默认值机制；
- 单人游戏可以从该界面编辑本地世界服务端配置；远程多人客户端不得用本地 `SERVER` TOML 覆盖服务器规则；
- 原版“选项 → 辅助功能设置”的可滚动列表提供半宽“配方书”（英文 Craftable）入口，中文主页名为“配方书设置”：末行只有一个半宽控件时补右侧，否则新开左侧条目，不拆满行或全宽条目。保留原条目及 option 映射，列表负责滚动、键盘和旁白，重复初始化不能重复添加。独立主页以双列直接显示六项个人草稿选项，不再保留个人设置二级页；底部说明以上部分个人偏好受当前世界规则影响，不向主选项页添加按钮。个人六项、世界基础规则和直接部分准备子页共用已注册 `ConfigValue` 和标题/Tooltip/默认/范围/枚举元数据，多选策略说明在同一翻译定义中逐项换行，不增加平行定义或 TOML。辅助功能列表只提供入口，不内联扫描、交易、掉落物或时间压缩等玩法规则；
- M1 将完整扫描设置纳入缓存身份，范围、缓存时间或末影箱策略变化后旧快照不能复用；
- 客户端偏好不能放宽服务端限制；
- 配置项使用翻译键、范围说明和重启/即时生效标记；
- 配置迁移需要版本号，未知旧值记录警告后回落到安全默认。

主页个人控件只改草稿，footer 从左至右为“取消 → 默认值 → 完成”：“完成”通过注册 spec 校验并保存已改项，“取消”/Escape 不保存，“默认值”也需完成后才写入。普通世界入口随上下文区分：单人未开放局域网且 SERVER 配置已加载时进入基础规则和直接部分准备规则入口的世界草稿页，采用相同 footer 顺序与草稿语义，不显示诊断 TTL；该编辑页没有常驻来源说明或重新读取按钮。直接部分准备子页复用三个实际注册值，不另建配置；从该页取消不撤销专业页已经保存的变化。远程/LAN 进入只读查看页，显示当前连接/世界下最近读取的规则快照，footer 从左至右为“重新读取规则 → 完成”，不在规则列表内放来源文字或重读条目；读取状态、来源与错误由重读按钮 Tooltip 和旁白提供，pending 时禁止重复读取。未进入世界时入口禁用，SERVER 尚未加载时不能编辑。编辑期间换世界或开放 LAN 时立即禁止保存。未同步或超时不以本地 SERVER TOML 补远端真值，远程 OP 也没有改规则载荷。NeoForge Mods/高级专业配置保留原生入口、权限、校验和保存，以及其自身“取消（UNDO）→ 重置（RESET）→ 完成”的顺序与生命周期；不得因位置一致而将其取消解释为普通页草稿取消。专业 SERVER 配置未加载时同样不能编辑，不提供未来世界模板编辑。

进入专业配置不隐式保存普通页草稿；返回新主页时，已改项目保留未保存意图，未改项目刷新同 spec 的最新值。专业页沿原生方式修改和保存，其已保存的变化不由普通页取消撤销；这不是第二套配置或针对专业页的回滚层。

普通名单子页按产出物品 ID/配方 ID 排序并提供名称/物品 ID/配方 ID 搜索，每配方是默认/允许/需确认三态，成本 Tooltip 说明真实默认结构与输入/产量；当前显示最多 256 条，超出须缩小搜索，不建设独立通用配方浏览器。子页完成只把列表合回父世界草稿，父页完成才保存。合法未知 ID 可手动保留，但暂不生效。专业名单编辑器与 TOML 共用整表校验，因为 NeoForge 235 的默认列表编辑器只检元素不能保证总条数边界；取消/UNDO 和保存仍沿原专业生命周期，不因自定义编辑器形成第二套配置。
