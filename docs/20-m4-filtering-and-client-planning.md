- 范围：解决当前原版“仅可合成”全范围收敛问题，并分担浏览搜索负担；不增加配方类型、容器、工作站、JEI、撤销或历史路线。
- 决策：[ADR-0008](adr/0008-snapshot-scoped-client-planning.md)。发生冲突时，本补充只替代旧文档中的浏览计算位置、资源同步和完整方案验证方式，其余 M4 语义不变。

## 1. 代码取证：实际瓶颈与已经有的机制

下表为迁移前取证，不是当前实现清单。第四批已把正式配方书切换到客户端 FULL_ONLY 与按需诊断，删除旧线上批次入口；旧 payload/客户端队列只在测试源码保留，不能充当暗中回退。服务端旧批次核心仍供历史性能夹具对照，不再由网络调用。

| 现有位置 | 已核对的行为 | 改动理由 |
|---|---|---|
| `RecipeBookStatusHandler` | 筛选时查询当前分类/搜索内隐藏候选；最多 32 个 ID，至少 4 tick 间隔，单在途，超时 40 tick | 隐藏项必须发现，但不应逐批往返才能推进整个目录 |
| `ClientRecipeStatusStore` | 普通结果按 10 tick 鲜度再次请求；未知有更短重试 | 稳定资源下重复刷新不是必要的资源验证 |
| `CraftingService.BatchPreview` | 一批共享来源复制、索引和 Reachability；每个目标用 `partial=true`；容量模拟仍读玩家库存 | 共享生命周期过短；过滤否定项不需要部分搜索/详细缺口 |
| `CraftingSessions.previews` | 已按配方访问身份、规则、资源指纹等复用结论，LRU 上限 256 | 不是“没有缓存”；全范围超出容量时会淘汰后重算，缓存身份也需覆盖完整交付容量 |
| `EnvironmentSnapshotService` | 扫描编号递增，快照包含活端点；缓存可用时仍从端点复制当前栈 | 扫描世代不等于资源内容版本；不能把该快照发给客户端或直接交给线程 |
| `CraftingRecipes` / `CraftSearch` | 已有共享索引/依赖、同一账本搜索；assemble 访问 ServerPlayer、Level、注册表和 CommonHooks | 不能简单把现类放到客户端工作线程；需要剥离不可变输入与权威组装边界 |

多人负载不必然“几何倍增长”：重复目标成本、每玩家资源规模、候选组合及公平限额共同决定开销。优化目标是消除每玩家每目标的服务端浏览搜索，而不是承诺服务端成本与人数无关。扫描、复制、授权、网络和执行仍有成本。

## 2. 对四项建议的取舍

1. **采纳同一资源版本共享闭包。** 沿用原 Index/需求关系；动态 Reachability 从单批扩为同一资源版本的浏览会话。事件式前向传播若优于现闭包扫描，只替换原实现，不能保留两套常驻推导器。
2. **采纳候选精确判定与查询目的分离。** 隐藏筛选项只求完整一次；可见项、悬停及主动详情按优先级补部分状态/诊断。不因过滤失败就执行部分搜索。
3. **采纳内存版本复用。** 分类/搜索只改变工作队列与投影，不清除同版本已完成结果。M4 先整份资源版本失效；基于反向依赖的局部失效延后，容量和权限不是简单原料依赖。
4. **采纳持续推进，不建设双重服务。** 最终由客户端本地队列持续计算，服务端持续维护授权快照。不上另一套服务端全目录推送求解系统。现服务端单目标求解保留给明确 C、必要诊断及不支持本地求值的有限回退，不允许回退为几百个目标轮询。

在 M4 关闭前分两段实施：M4.8 完成版本化筛选和客户端浏览；M4.9 为受支持的完整固定数量方案增加服务端见证验证。它们是有边界的架构迁移，不应声称为简单扩大缓存的小修。若门禁失败，应停留在上一个安全实现并重新评审，不静默把其标为完成或挪到 M8。

## 3. 一个核心，不是两套算法

8c 当前实现边界：新增且只新增 `recipe.PlanningInput` 这一窄值输入类；原 Index 冻结普通需求的标签成员和默认输入余料，复用原候选关系。`CraftSearch.run()` 和 `advance()` 使用同一个 frontier/闭包状态机，前者同步推进至终态，后者可暂停；没有保留旧算法体。预览和执行前的搜索不再读取 Level/玩家/活容量，原 `CraftingRecipes.validate` 在服务端对选定步骤调用真实 matches/assemble/getRemainingItems 复验；不符或预算超限即拒绝，不搜索替代路线。此处复验的是服务端自产计划，不是 M4.9 客户端见证入口。

纯值模型仅接受原版有序/无序实际类型、可规范化为物品集合的需求、原版输入物品；未知自定义条件不在搜索中调用。若缺口存在不能用纯值模型覆盖的候选关系，不得把省略候选当成充分无解并授权部分消耗，返回不支持/未确定。该边界不会宣布第三方配方兼容；8d 不支持本地模型时的有限主动入口仍按本设计另行落地，不自动回到全目录服务器搜索。

### 3.1 提取边界

- 权威配方/标签由服务端决定；原 `CraftingRecipes.Index` 的规范化规则和索引算法提取为两端共用代码。两端各自持有运行时关系实例，不跨 JVM 共享对象，也不默认传输服务端已学习的关系；磁盘缓存仍只在服务端存档内。具体所有权与构建决策见 3.4。
- 将不可变目录视图、规则/解锁/工作站视图、资源值和容量布局作为 `CraftSearch` / `ResourceLedger` 输入；搜索排序、回溯、循环、现物优先、剩余物账本及预算逻辑只有一份。
- 不能让纯核心构造 `ServerPlayer`、读取 Level/活库存，或调用可变 RecipeManager、Ingredient 扩展回调、CommonHooks。注册表/标签读取和普通配方规范化在对应游戏线程完成，再发布防御性复制的数据。
- 从现 `MainInventoryInsertion` 提取不依赖活库存的容量模拟，服务端也调用同一实现；执行写入仍留在原事务。不能给客户端另写简化的“空格数足够”算法。
- 普通有序/无序配方的安全输入匹配、输出和剩余物值由同一规范化路径生成，服务端真实组装保持权威复验。未证明可纯化的类型/组件/平台回调标记为本地不可判定，不能套用默认配方结果。
- 同一模型既可在服务端同步求解单目标，也可在客户端有界调度。实际配方回调不能因为模型“只读”就被认定线程安全。

### 3.2 闭包不是数量证明

存在性闭包是宽松候选集：需求内材料为 OR、一个配方的需求为 AND；重复槽位的数量交给账本。相同需求引用共享关系，无库存起点的转换环不能自激活。闭包保持 09-13 的宽松权限策略以免错误锁定诊断；精确搜索仍逐配方校验工作站、权限、材料及容量。

完整且覆盖本地支持目录的闭包，可以排除没有任何生产起点的候选；未完成、被截断、缺少不支持的关系时只能给未知。一个原木能到达木板和木棍，不证明它同时足够制作木镐。每个目标的数量账本独立，闭包和可合成状态不能充当资源预留。

### 3.3 结果精度

同一 `ClientRecipeStatusStore` 增加查询目的/证据级别，不新增第二个状态库：

- `FULL_ONLY`：完整可行、已排除完整、未知。已排除完整不等于 BLOCKED，也不等于已知 PARTIAL；不生成解释图、完整缺口或部分执行计划。
- `DIAGNOSTIC`：沿用完整/部分/不可行与原因，可填充已有三态；可见普通页面低优先级补齐，悬停与详情提高优先级。
- 证据的共同身份包含连接/玩家隔离、配方世代、资源版本、目标配方/批次、规范化约束和影响可行性的有效规则/策略。查询目的不是彼此隔绝的缓存键：FULL_ONLY 与 DIAGNOSTIC 是同一条记录的能力层级，按 3.5 升级，不能切用途就重复完整搜索。
- “仅可合成”仍按按钮内任一候选完整可行为准；图标轮播不是请求身份。没有完成数量/容量检验就不能标绿。未知暂不进入该筛选，但必须能看到整体待确认/搜索限制状态，不能伪装“全部查完”。

### 3.4 静态知识：四层所有权与构建决策

09-16 实施落点：Catalog 与原同步 Index 共用 Builder，逐配方规范化、逐条发布、逐需求预热；第四批已由 ClientBrowsePlanner 在正式连接/世代下持有。首份服务端世代到达后再构建；模型语义指纹在同一 Builder 中逐条折叠，菜单关闭不清静态图。此前目录分片超额样本（最大 10.3899 ms）仍保留，不以单轮切换成功抹去帧门禁。默认继续本地构建，不增加图同步。

| 层 | 所有者与复用规则 |
|---|---|
| 权威配方、标签、支持范围 | 服务端决定，客户端使用已经同步且握手匹配的数据；客户端文件不是权威 |
| 规范化规则、索引/邻接算法 | 两端使用同一份代码，归原 recipe 边界；不是两套算法 |
| 运行时目录与关系图 | 两端各自持有，按各自连接/服务端的配方世代复用；相同需求只建一次，懒构建未完成与完整空邻接分开 |
| 磁盘缓存 | 仅服务端存档内 M4.7 缓存；客户端不新增持久文件 |

默认先在客户端从已同步权威配方构建同模型关系，**不实现关系图同步协议**。M4.8a 测一次客户端目录规范化/关系构建的 CPU、P95/峰值、分片帧成本及内存，并将首次用到的懒构建工作计入，不只测创建空 Index 的时间。若其不妨碍 8.1 门禁，就保持本地构建。

仅当同版本复用后，这部分仍是冷页的主要瓶颈并导致门禁失败，才允许提出有界规范化关系传输。先用测试夹具对比本地构建与“服务器导出+编码+真实 RTT/传输+客户端验证/绑定”的总成本和字节；只有净收益明确且安全验证不缩水，才修订 ADR/载荷上限后实现。接收仍绑定原索引模型、校验内容指纹/完整性，不新建图服务；同一世代只选一种初始化来源，不双重建立/常态双跑。握手必要的规则/支持元数据不等于同步整图，不能借其绕过这个决策门槛。

客户端关背包、换分类/搜索、换普通菜单、材料变化、授权续期都不销毁静态关系实例。断线释放；重连或配方/标签运行时世代变化时重新绑定/构建，不能只凭相同内容指纹沿用旧句柄。维度变化而配方世代未变可保留静态图，但必须重建资源授权。静态图不预计算全体动态结果，无界占用或不支持数据仍按原上限处理。

### 3.5 证据升级，不从头重做已证明的阶段

一条记录分别保存完整证据、可选诊断及证据来源。完整证据至少区分 `FEASIBLE`、`EXCLUDED`、`UNRESOLVED`；根不支持/缺工作站/未解锁等前置拒绝另记，不能冒充允许部分分析的缺料证明。所谓 EXCLUDED，是在当前支持语义和相同约束下，所有需要的完整分支已穷尽或被有效必要条件排除；候选/深度/状态/时间任一截断都不是该证据。

完整阶段身份按“制作完整目标”规范化，不把请求的 `partial` 意图位或 FULL_ONLY/DIAGNOSTIC 名字放进该身份；否则双击/诊断永远无法命中完整失败证据。部分阶段另外匹配其安全准备策略。改变任何影响完整可行性的实际策略（例如余料容量规则）仍必须失效；不能为提高命中率忽略真实规则差异。

| 已有证据与新用途 | 处理 |
|---|---|
| 同身份完整 FEASIBLE → 筛选 | 直接使用，不搜索；不会因为 FULL_ONLY/DIAGNOSTIC 不同再建一条独立结果 |
| 同身份完整 EXCLUDED → 诊断/部分 | 跳过已完成的完整搜索阶段，直接运行原核心的缺口/部分分析；若受前置安全拒绝则只解释拒绝，不部分执行 |
| UNRESOLVED/预算耗尽 → 诊断 | 不可跳过完整判定；没有可靠失败证据时不能自动部分完成 |
| 已有诊断 → 筛选 | 复用其中完整证据，不将 PARTIAL 当完整可行 |
| 数量、手选约束、资源或有效规则不匹配 | 不套用旧证据；创建新身份下的计算 |

纯核心提供明确的“完整阶段完成 → 诊断/部分阶段”入口，复用闭包和完整失败标记；不靠伪造 `completeSearch` 布尔值强行进入部分搜索。阶段可共享有界缺口摘要，但无需为所有失败目标保留 frontier。部分分析可以遍历必要的准备分支，这与再次执行完整搜索不同；必须分别计数以证明没有重复完整阶段。

普通目录只保存结论/证明种类及小型原因，不存所有完整计划。客户端最多保留当前悬停和当前详情各一份候选方案（同目标共享一份，合计最多 2 份，每份沿 128 步/64 KiB 编码上限，解码内存计入会话总额）。焦点变化释放被替代方案，结论继续保留；资源/世代失效立即清理方案。FEASIBLE 若未保留方案，详情或制作时允许为该单目标重新提取见证，此成本必须单列，不声称“有一个布尔结论就能还原计划”。不能因此让所有筛选目标持久保留步骤。

客户端证据只用于本地计算/展示。服务端可复用自己产生且身份仍匹配的 EXCLUDED，不能接收客户端的否定标志作为证明；服务端复用规则见 6.3。预算/超限元数据不是失败证明，也不能通过切换查询目的重置累计工作上限。

## 4. 快照授权与版本

### 4.1 两种快照

09-16 实施落点：BrowsingSnapshot 与原 CraftingSessions 捕获/稳定引用已接入协议 7。外部受保护栈不进入投影；主背包保留原版已知准确组件用于净容量。底层身份只留弱引用，双箱包装不改变资源身份。客户端完整校验、分片解码、模型指纹与独立租期满足后才展示本地正结果；不把这份快照当作执行授权。

现 `EnvironmentSnapshot` 保留为服务端主线程活端点视图。新增的浏览快照仅为不可变值投影，不持有活对象、不授予取物权、不持久化：

- 连接会话 ID、菜单会话 ID（不能只依赖可能复用的 containerId）、配方/标签运行时世代、规则版本、资源版本、有限有效期。
- 当前玩家可使用的工作站能力、有效策略、配方解锁/limitedCrafting 信息；客户端偏好只能收紧服务端规则。
- 已授权且可投入的精确栈值/数量，以及主背包 36 格的容量布局。外部来源只用本会话的不可猜测/不透明引用，不发送坐标、真实槽号、容器名或活句柄。
- 主背包与外部资源不能只合成一个总数：从主背包消耗会释放空间，从箱子消耗不会。保持服务器来源优先级与来源到容量位置的必要映射，否则满背包预览会错。
- 默认受保护的外部栈无需公开名称、书内容、附魔或 custom_data；主背包受保护槽可以只公开不可投入的占位/安全容量描述。若脱敏会丢失所需的堆叠或匹配语义，此项转为未知/主动服务端验证，不猜测等价。

授权范围仍由原扫描器决定，锁、遮挡、未加载区块、未解包战利品和无权访问容器不进入投影。末影箱只包含当前玩家已授权的个人资源。绝不把 A 的资源快照发给 B，不能在日志/磁盘记录内容。

这比旧协议只返回配方状态披露更多信息，必须明确承认。禁止未授权信息泄露；也不能声称客户端看不到已获授权的材料数量。权限撤销只能停止后续同步，无法收回已经发出的数据。

### 4.2 稳定内容版本

资源版本由服务端对**影响计算的规范化内容**比较后分配，不能直接用扫描计数或仅用一个无碰撞保证的 hash。比较内容含所有投入栈、主背包空槽/堆叠容量、保护判定、工作站、有效权限/解锁、规则及稳定来源映射；明确排除捕获时间、授权到期时间、心跳序号、扫描计数等传输/租期元数据。扫描相同内容不产生新资源版本。

| 变化 | 静态图 | 动态闭包/结果 | 授权 |
|---|---|---|---|
| 配方/标签运行世代变化 | 重新绑定/构建 | 全部失效 | 撤销旧授权/确认，重新取得 |
| 材料、容量、工作站、有效权限/解锁或规则变化 | 保留 | 新资源版本；M4 先整份失效 | 发布新版本授权 |
| 复查一切未变 | 保留 | 版本不变、闭包不重建、已完成目标不重算 | 仅续期 |
| 租期届满但尚未复查 | 保留 | 暂停使用/展示为待确认，可保留有界证据但不重新搜索 | 不能使用旧租期执行；复查相同内容后恢复已有结果 |
| 仅分类/搜索变化 | 保留 | 已完成结果保留，取消不再需要的未完成目标 | 不重新申请相同资源 |

来源引用在同一浏览会话内稳定：首次为服务器规范化端点身份+槽分配不透明引用，复查同一端点/槽沿用引用和确定性来源顺序，不随遍历次序重新编号。库存数量变化沿用引用但更新资源版本；端点被替换、双箱重组、失权后重新授权时撤销旧引用，旧编号不再指向新对象。不跨玩家/连接共享映射。不能每次扫描生成随机引用后再把引用差异当资源变化。

配方/标签重载无论内容指纹是否相同都开启新的运行时世代，重建运行期对象并撤销旧快照/确认。移动须重新检查授权范围；如内容完全相同可复用数学结果，但不能复用旧来源授权。

M4 不假定所有箱子、漏斗、其他玩家操作都有可靠变更事件。采用事件触发失效加受预算约束的周期复查：目标复查周期 10 tick，变更事件尽早标脏，完整重扫沿用扫描规则并计时。未及时完成复查时，在声明鲜度截止后将旧绿状态置待确认；不能靠延长 TTL 保持绿色。

多 tick 准备资源投影不得拼接两个版本：先复制值，再验证来源/容量/权限未变，才原子发布；冲突则丢弃并有界重试。快照读取不占用资源、不中断容器正常使用。频繁变化时可显示等待稳定，主动执行仍读取新鲜世界。

### 4.3 同步与生命周期

- 服务端按菜单/连接建立一个浏览会话，首包完整快照，后续先采用“未改变则续期、有改变则替换”的有界全量投影，不立即建设通用增量复制协议。字节量不达标再在同一模型内加入带 baseVersion 的差量，不同时维护两种真值。
- 大投影分块：完整性/数量/字节校验全部成功后才发布，不将半份资源交给搜索；旧/乱序/重复/跨会话块丢弃，有超时和有限重同步。任何截断都须显式未知，不能少算资源后宣布不可合成。
- 客户端按 3.4 默认从已同步原版配方建立同模型目录；与服务器发布的支持范围/规范化语义指纹握手，包括标签、保护/安全准备规则版本、输出及剩余物语义。关系图传输须独立成本证据和 ADR 决策，不能因握手存在就默认导出整图，也不复用磁盘文件作为网络协议。
- 握手不匹配则不发布本地确定结论，不接受见证；明确提示并保留限流的主动服务端入口。不自动回退成全目录服务端搜索。
- 关闭菜单、死亡、维度/模式切换或失去授权，取消动态工作/同步、清理候选方案和令牌；静态图按 3.4 保留。初版关闭菜单释放动态资源/结论，下次打开须新快照；不承诺跨菜单复用动态结果。断线/配方世代替换另释放/重绑静态图。创造与旁观仍零浏览请求、零本地求解。分类/搜索变化只取消旧范围不再需要的未完成目标，同版本已完成证据保留。

### 4.4 接收期限与发送配额的相容规则

初版不压缩资源投影。声明的总数据量 B 不超过 4 MiB，**数据块有效载荷最多 31 KiB**，每块头部最多 1 KiB，整块编码后不超过 32 KiB。块数 C = ceil(B / 31 KiB)，最多 **133** 块，替代旧 128 块限制；空投影用一个受限元数据消息完成。总字节、块数、各块长度与声明必须一致，重复块不计入进度，也不能多次分配内存。

沿用全服 128 KiB/tick、单玩家 32 KiB/tick 的浏览发送配额（含块头）：每 tick 最多发送 4 个满额块。**同时已准入的数据传输最多 8 份**，受全服内存上限进一步收紧；既有发送循环持轮转游标，每份每轮至多一块，新传输加入队尾。因此在有可用发送预算/连接正常时，一份可发送传输最多每 2 个服务器 tick 获得一次发送机会。控制/撤销消息优先，偶发让出由总期限余量容纳；持续过载不承诺传完，须明确结束为同步未完成。

分别使用两种计时，均由本地单调时钟计算，50 ms 为一个 tick 等值，不能用可能停滞的世界 gameTime 冻结超时：

- **无进展超时：100 tick 等值（5 秒）。** 从接受传输头开始计时，只有收到本传输一个新的、校验通过的数据块才刷新；心跳、授权续期、重复/非法块均不续这个期限。
- **总接收期限：D = 100 + 2 × C × ceil(8 / 4) = 100 + 4C tick 等值。** 从接受传输头开始固定，不随新块或参与人数变化滚动延长；至多 632 tick 等值（31.6 秒）。其中 2 倍发送轮次容纳调度让出，另有 100 tick 等值用于网络抖动。4 MiB 对应 C=133，满额无竞争约 133 tick，8 份竞争约 266 tick，均不因原来的 100 tick 总期限而必然失败。

服务器发出传输头前必须完成数据/内存准入并占有发送名额；没有名额只返回小型“等待准入”，不让客户端先分配大缓冲。等待名额最多 100 tick 等值，按轮转准入或明确拒绝；客户端明确操作可以重新申请，但等待/拒绝消息不自动重启接收计时或计算任务。接收中最多一次有界自动重同步，沿用首次传输头起算的总期限，不能借新传输 ID 无限续命；正常资源版本替换是新身份，但旧缓冲/工作须先释放并受同一准入限额。

完成接收不代表获得新授权：仍须匹配当前资源版本和未过期租期，必要时由服务端复查相同内容后续期。传输超过 10 tick 不自动改变资源版本，也不允许客户端用传输总期限替代授权鲜度。任一接收期限到达即释放未完成缓冲，显示同步未完成/可重试，不发布半份资源或错误不可合成。上述上限是允许的边界情景，不将最大快照的长传输时间混入普通原版 2 秒筛选目标的已达标声明。

## 5. 调度、容量和更新

M4.8 首先在客户端游戏线程使用可恢复、只读的有界分片，把现搜索局部 frontier/账本变为短期 continuation；同步服务端调用同一状态机跑到截止。一个范围不为每个目标创建线程或同时保存大量展开栈。纯模型隔离通过前不上工作线程；若分片仍影响帧时间，另用同一核心的单工作线程，但必须先有不可变/取消/重载测试，不并行保留两条调度管线。

默认优先级：明确交互/悬停 > 当前可见候选 > 筛选隐藏候选 > 可见部分诊断 > MAX；实际派发必须服从 5.4 的“最多三个前台片后一个隐藏片”保底规则，不能仅靠优先级排序。客户端换范围不需向服务器再要相同资源；显式刷新按下述准入规则处理未知项，不清除同版本成功/充分失败证据。

### 5.1 分片、停止、取消与重试的唯一含义

| 事件 | 搜索状态处理 | 下次行为 |
|---|---|---|
| 本 tick 的软时间片到期，当前阶段总预算仍有余额 | 保留 frontier、账本、visited、阶段/游标和累计计数 | 下一片原地继续，不重建根任务、不增加“重试次数” |
| 当前阶段累计时间/状态/候选/深度限制耗尽 | 释放该 continuation，标记此阶段未确定；保留先前已完成证据 | 完整阶段耗尽不得变成 EXCLUDED；诊断耗尽不抹掉已有完整失败证据；该阶段同身份被动停止 |
| 资源/配方世代变化 | 取消旧 continuation，旧结果失效 | 新身份下开始，不能接着使用旧账本 |
| 分类/搜索变化且目标仍在新范围 | 保留该目标进度 | 按新优先级继续 |
| 分类/搜索变化且目标不再需要 | 释放该目标未完成进度，保留所有同版本完成证据 | 返回时未完成目标才可重新开始，累计已花费预算元数据不因切范围清零 |
| 授权暂过期而内容未证变化 | 暂停动态计算，保持有限进度/证据 | 同内容续期后继续/恢复显示；真正撤权则取消 |

删除新版“被动耗尽最多 5 次”的政策。它只属于协议 6 的旧 BatchPreview 重试实现，M4.8d 切换完成后不得残留为隐藏回退。每个规范化身份的额度明确为：

- **完整阶段：累计最多 8 ms 实际 CPU、2048 个展开状态。** 包括现物快路径及完整搜索，不包含让出后的等待。FULL_ONLY 到此为止。
- **诊断/部分阶段：按需另有累计最多 8 ms、2048 个展开状态。** 只有明确诊断需求（当前可见项补诊断、悬停或详情）且完整阶段已充分失败、前置条件允许时才启用；额度只能用于缺口/部分分析，不能再跑完整搜索。诊断未完成时保留充分完整失败，只把部分/原因标未知。
- 每阶段仍受深度 12、单需求候选 16 等上限；每身份每阶段默认仅一次被动累计尝试。完整与诊断都执行时最多合计 **16 ms/4096 状态**，不是每次悬停各给一份。共用闭包另按 5.2 的每资源版本额度只计算一次。
- 所有阶段、共用闭包、静态关系准备和 MAX 都从同一客户端 **2 ms/tick** 软调度额中支出，没有“每目标 2 ms”或额外诊断线程。服务器主动处理仍受既有每请求 8 ms/全服 16 ms 准入；本段的客户端分阶段额度不扩大服务端请求上限。服务器若在同一请求先完整再部分，两阶段共同使用该请求余额；已有服务器充分失败证据则直接将请求额度用于部分阶段。

主动刷新/详情可经限流申请一次新的有界尝试，日志区分“人工重试”和“续片”；不会因定时器、悬停渲染、用途变化或租期续期自动重置。取消后返回目标如需重建，消耗原被动尝试剩余预算；无余额则待主动重试。网络分块超时后的有限重传只负责传输，不能触发计算从头开始。确认/提交仍禁止自动重试。

### 5.2 闭包优化的固定顺序

1. **先延长复用范围，不换算法。** 在当前资源版本的动态会话内维护一个 `NOT_STARTED/BUILDING/COMPLETE/UNRESOLVED` 闭包槽；所有目标引用它。第一次需要生产关系时触发，完整后不因目标/分类/搜索/授权续期重建。现物快路径不必等待闭包。一次构建可跨片，但 BUILDING 不能被其他目标当作完整集合。
2. **只测这一次构建。** 记录构建/续片次数、目录扫描轮数、需求访问数、总 CPU、帧分片和内存；与数量搜索分别计时。闭包准备独立记账一次，受 2 ms 客户端片额和初始每资源版本 8 ms 累计准备上限约束，不能每个目标重新领取一份预算；超限为 UNRESOLVED，按 5.1 停止，不能发布假完整闭包。若基准推翻初始额度，先评审优化/参数，不隐式扩容。
3. **只有复用后仍为瓶颈才替换实现。** 若闭包仍是全范围关键路径、造成 8.1 门禁失败，才在原 Index 内增加“材料 → 使用该材料的需求/配方”邻接；用前向队列替换目录反复扫描。需对照 CPU、邻接建造/驻留内存与冷启动总成本，有净收益才采用；正常实现只留一种闭包算法，旧实现可作为测试对照，不做运行时双跑。

邻接按配方世代复用；一次闭包的需求满足计数、队列和库存起点仍按资源版本建立，不放入静态知识文件。它只加速**一次闭包构建**，不授权按材料变化局部失效结果。M4 仍在材料/容量/权限等变化时整份动态失效；局部失效留待 M8。

### 5.3 容量与调度上限

初始实施上限（测试校准基线，非已达标数字）：

| 项目 | 初始限制 |
|---|---|
| 浏览会话/工作 | 一个活动浏览会话、同时只运行一个目标；最多两个 continuation（前台/隐藏各一），一个最新前台候选和一个替换范围；无历史任务队列，见 5.4 |
| 纯计算 | 全客户端共享 2 ms/tick；完整阶段 8 ms/2048 状态，按需诊断阶段另 8 ms/2048 状态，最多合计 16 ms/4096 状态，不把诊断额度借给完整阶段；跨片累计不重置，见 5.1 |
| 同资源尝试 | 每身份一次被动累计尝试，跨 tick 续算；耗尽即停止为未知。主动重试须明确操作/限流，取消返回不重置被动计数；无“五次从头被动重试” |
| 目录/结果 | 跟随当前支持目录，最多 16384 配方状态；每连接总快照/结果/continuation 估算内存上限 16 MiB，状态只保留结论/必要诊断，非每目标完整计划 |
| 静态目录 | 每客户端连接的不可变目录/共享知识估算上限 64 MiB，计数沿 M4.7 支持范围；它与动态会话分账，不能把目录内存漏计或按目标复制 |
| 资源同步 | 最多 4096 来源栈、4 MiB 数据；数据块 31 KiB + 最多 1 KiB 头，整块 32 KiB，最多 133 块；传输/解码计数先限长，见 4.4 |
| 暂存/期限 | 每连接一个已发布和一个接收中快照；无进展 100 tick 等值，总期限 100+4C、最多 632 tick 等值；新块不延长总期限，见 4.4 |
| 服务端全局 | 快照准备/同步计入既有主动/被动总准入，16 ms/tick 软上限不增加；全服浏览会话估算内存上限 64 MiB，轮转玩家，不以先到占满 |
| 发送公平性 | 全服 128 KiB/tick、单玩家 32 KiB/tick（含块头），最多 8 份已准入传输，逐块轮转；控制/失效优先，超载按期限明确退出，见 4.4 |
| UI 投影 | 常规结果每 4 tick 合并一次、每帧最多一次；范围变化和授权失效及时处理，不按每个完成目标重建列表 |

超限明确拒绝/待确认并保留主动单目标能力，不能截断目录伪造“全部完成”。上述量相互制约，不能因为记录数合法就忽略总内存/字节。客户端结果上限解决原 256 项缓存抖动，但不意味可无限增长。初版不做局部依赖失效或压缩协议。服务端可保留有界的来源引用到稳定端点身份/槽索引的值映射以重新绑定，但不跨 tick 保存活容器；其容量计入会话总额。总内存不足时明确准入退避，空闲会话限时释放并轮转名额，不让先到玩家永久占满。

### 5.4 隐藏候选保底：3 个前台片后 1 个隐藏片

不新增调度框架，在原客户端协调器使用一个 0..3 的前台服务计数、前台/隐藏各一个 continuation 槽，以及原范围列表/已完成结果表。09-17 根据“单个轻量目标仍占一个 tick”导致五轮筛选约 2.01–2.10 秒的证据，窄修订原“每 tick 最多一个片”的保守规则：整个 tick 共用一个 2 ms 截止点，提前完成可继续派发，最多 64 次；每次重新检查截止点，不给新目标另一份 tick 额度。未完成 continuation 仍原位续算、累计目标预算不变。不得同 tick 无限派发。

1. 当前筛选范围有可推进隐藏工作时，最多连续派发 **3 个非隐藏片**；下一次派发必须给隐藏工作一个片（可在同 tick，最晚下一可调度 tick），并将计数清零。无前台工作可立即服务隐藏；隐藏等待所必需的同版本闭包准备也算隐藏工作，不因前台持续操作延后准备。
2. 隐藏目标按稳定去重 ID 队列顺序，一个目标持续保留到完成/累计耗尽再推进队首。若它转为可见/悬停，提升同一个任务而非复制任务，其进度和阶段额度不变，隐藏游标推进到下一项。同一目标在两类队列之间只保留一份状态。
3. 鼠标移到另一物品只替换一个“最新前台候选”ID，不销毁当前仍在有效范围内的前台/隐藏搜索；正在运行的前台阶段到完成/累计耗尽边界才切换。显式详情可在片边界接管前台槽：原任务若不再需要按 5.1 取消，仍保留累计消耗；**不得清除隐藏槽或公平计数**。详情覆盖层开启期间，父配方书的筛选范围仍有效则隐藏工作继续享有配额；真正关闭菜单/改变资源版本才取消。
4. 在授权有效、版本稳定、客户端正常 tick、隐藏前置依赖已就绪时，队首隐藏工作从就绪到下一次派发 **最多等待 4 个客户端 tick**（20 TPS 下约 200 ms），持续悬停/详情操作也不得突破。此为获得计算片的上限，不是每个隐藏目标完成或整个队列完成的承诺；后排目标还需等待前面有限工作的结束。
5. 无有效授权、同步/闭包不完整、游戏暂停或不可抢占调用超时等阻塞，分别记录原因与墙钟等待，不伪装为公平达标。一次调用突破软片额时不得追加另一个完整片补偿；记录实际帧成本。公平计数不因鼠标、详情或小型范围改动反复清零；只在已无隐藏需求或会话结束时清理。

两个 continuation 都计入现有 16 MiB 动态会话总额，不是并行线程或每目标状态池；这是对旧“仅一个保留中的目标”限制的窄调整，用于切片公平且不丢进度。用户最新前台意图仍有优先机会，但不能依靠持续制造前台请求剥夺隐藏工作。压力测试须同时报告队首派发等待、每个隐藏目标总排队时间、完成/未知比例和前台响应。

8c 已为单个 continuation 的 frontier、memo 和预像建立 **4 MiB 保守估算限额**，在创建分支/状态键前检查；共享预像重复计数，不低估为只有栈深度。达到限额返回未确定，不授权部分制作。两个任务预留至多 8 MiB 估算空间，为 16 MiB 会话的资源、结论与方案留下余量；这不是实测 JVM 堆硬上限，也不代替 8d 的会话总额/准入。`cancel()` 是终态，不能重新绑定已开始任务的 scope/证据/额度；后续调度器还必须按身份保留取消后的支出/结论，禁止通过创建新任务绕过累计上限。

## 6. 服务端验证客户端方案（M4.9）

### 6.1 先区分可行见证与不可行证明

完整有序方案能作为“存在一种合法做法”的见证，服务器不必重找路线。客户端“没有找到完整方案”“最大只能做 N”“这些是最有用的部分材料”不能用一条成功路线证明。

因此 M4.9 只接纳**完整、固定数量、受支持普通配方**的见证；部分完成及双击的失败关联仍由服务端原求解器证明/裁定。MAX 在客户端可搜索，但成功见证只证明下界；未知不得标实际最大值。点击该数量最终按完整固定数量验证，不授权更多产量。服务端无需替浏览者证明全目录不可行或全局最优。

### 6.2 最小见证，不接受写入指令

通过原 CraftingService 新增有界输入分支，不另建执行服务。载荷携带：会话/资源/配方世代、唯一操作序号、目标/批次/有效策略/用户约束、有序配方 ID 与具体网格材料及资源/前序产物引用。客户端不指定世界位置、槽位写入、成品数量、经验、回调或可执行代码。

仍用 M4 的步骤上限 128、每步最大 9 槽、64 根批次，见证编码上限 64 KiB；所有集合和引用在分配/查找前限长，计数用检查溢出的运算，引用只能来自已授权来源或前面已验证步骤，不能引用未来/自身。来源引用只帮助定位，服务端重新绑定真实端点和数量；未知来源拒绝。

验证按以下顺序执行，失败零变更：

1. 先限长/限流/会话/操作序号检查，再读取新鲜资源和权限；撤销/过期快照不能变成永久授权。单 C 普通入口仍可由服务端求解，无本地方案也不影响基本能力。
2. 对服务端当前真实配方，逐步验证解锁、工作站、精确输入匹配，实际调用 matches/assemble/getRemainingItems；用同一个 ResourceLedger 和步骤模型逐项结算。忽略客户端声称的输出/成本/成功标志。
3. 检查每步从已授权库存或真实中间批次取材，来源不可重复承诺，完整配方批次不能拆分；累计步骤、材料、余量、剩余物全有界。
4. 从目标需求反向验证每个步骤的贡献，拒绝无关加工、无贡献循环、虚增批次或刻意制造“余料”。只允许满足实际下游需求所需的整批取整余量；共享批次分配由同一账本验证。该检查不搜索替代路线，不假借验证名义再跑全图。
5. 使用新鲜主背包重算主产物/余料/剩余物净容量和掉落策略；最终目标/数量/手动约束必须成立。将服务端重建的合法 CraftPlan 交给原唯一事务；保持提取前复验、托管、失败恢复和提交后通知。
6. 详情/混合路线/掉落等原有审阅要求保留：服务端规范化摘要与玩家已审阅内容不同则返回新摘要要求再次确认，不静默换配方或重试提交。确认令牌仍服务端签发、一次性、绑定玩家/菜单/意图/世代；可以重发紧凑见证供确认验证，但不长期缓存活计划。

对完整见证，旧“确认必须重新搜索”改为“确认必须新鲜验证并重建合法计划”；新鲜世界校验从未取消。坏见证不触发自动昂贵回退搜索，返回明确拒绝；正常用户可以重新请求主动规划。重复成功操作只返回已有结果摘要或拒绝，不再次提交。

不能宣称验证必然是廉价 O(步骤)：真实配方调用、输入/来源匹配、扫描及事件可能昂贵。验证与提交沿用现有全服准入并分别计时；恶意请求在廉价检查层先拦截。超过验证预算零写入，不分 tick 提交半个事务。

### 6.3 服务端自产失败证据复用

服务器在 `CraftingSessions` 原短期记录内保存自己求解得到的充分完整失败证据，不新建否定证明服务，不缓存全部玩家全部目标的计划。初版仅保留每玩家最近一个主动目标的完整证据及最多 40 tick 的双击关联；足够覆盖“首次 C 失败 → 同目标部分请求”。替换目标/过期/菜单或连接变化清理；状态与来源指纹为值，不保存活容器/搜索栈。

部分请求时仍新鲜捕获资源、权限、容量和有效规则，与服务器保存的完整身份逐项匹配。身份未变且原失败确为 EXCLUDED、无搜索截断、前置条件仍允许部分操作时，调用原核心的部分阶段，**完整搜索调用次数必须为零**。仅租期更新不破坏该证据；资源/数量/约束改变、证据过期或不完整，则正常重新完整判定。即使复用失败，部分计划仍须新鲜容量模拟和唯一事务复验。

客户端本地 EXCLUDED、客户端回传的状态/版本号或普通失败 toast 都不能创建服务端证明；无权限、预算耗尽或错误结果也不能作为部分授权。旧双击“首次成功后的第二次失败不得部分准备”规则仍由实际服务端操作序号/结果关联保证，不能只根据数学失败证据绕过手势验证。服务端必要时可返回自己的否定结论供显示，但不为接受客户端否定宣称新增证明协议。

体量预算修订：recipe/planner 现有 9 个顶层生产类，最多增加 1 个真正共用的不可变规划输入边界（合计 10）；优先在原模型拆离服务端包装，不能硬塞巨类。environment 最多增加 1 个浏览快照值边界；execution 最多增加 1 个窄职责见证验证器，仍由 CraftingService 调用；client 最多增加 1 个浏览计算调度器并替换旧批次职责。网络沿已有分组 payload 文件组织值记录，不每种消息建服务。不加通用 SPI、调度框架、第二图索引、第二容量器、第二状态库或客户端持久缓存。若实际安全分离需要突破该预算，先取证更新设计，不机械追求少类。

迁移退出条件：8b 的服务器浏览缓存/入口是临时基线，8d 后删除其专供全目录轮询的调度与重试职责；共用证据/闭包机制转由两端同模型承载，服务器仅按主动需求使用，不另留全目录预热。测试可以离线比较旧版本，不允许生产“双算后择优”。M4.9 开始前登记 M4.8 独立数据；M4.9 即使尚未通过，也不能恢复全范围服务器求解或把其安全失败混写成 M4.8 没有收益。

09-15 第一批迁移落点：`CraftingSessions.PreviewState` 直接替代旧预览 LRU，持有一个内容身份、一个 `CraftSearch.Reachability` 和至多 16384 个简短结论/失败证据，不保留执行计划。协议 6 暂用 200 tick 无请求清理和菜单/连接清理；它不是未来授权租期，也不代表关背包后已实现客户端静态图生命周期。`FullEvidence` 只能由完整搜索充分失败创建，绑定同一资源 scope 和规范化意图；未知不能创建证据，数量/约束/策略不同不能跳过完整阶段。容量模拟两个入口调用同一个值实现；索引构造、候选查找仍各只有一份代码。此批不放宽服务器预算、不接收客户端证据；完整失败后独立客户端诊断额度、continuation 与新协议需在后续步骤一起验证，不能以旧五次重试替代。

第四批浏览同步已使用协议 7；M4.9 见证接入若改变契约须继续升至至少 8，不能再把 7 当未占用版本。两端必须升级；集成服务器同样走同步、授权和验证边界，不用共享静态对象绕过协议。专服不得加载客户端计算/渲染类。

## 8. 验证与关闭门槛

正确性/安全至少覆盖：

1. 同快照全范围 FULL_ONLY 与同预算完成的原完整搜索逐项一致；有界未知单列，不能混入不可能；一个原木的木镐反例、部分木棍、转换环、标签竞争、锁定备选、同 ID 不同组件保留。
2. 稳定快照切分类/搜索/筛选超过 256 个根目标，闭包只构建一次、已完成目标不重算；数量/规则/容量变动则失效，只有分类变动不增加资源请求。含所有根候选轮播。
3. 背包空槽变化、堆叠余量、外部/随身来源差别、漏斗/他人操作、拆工作台、解锁、锁变化、末影箱、重载同指纹、换模式/维度/连接均检查授权与版本隔离。
4. 快照畸形长度/过量块/重放/乱序/截断/跨玩家/超时/哈希碰撞替身/缺失目录/篡改标签，不能泄露越权库存、崩溃或发布伪完整结果；无本地支持仍能主动请求合法目标。
5. 客户端改库存/配方/输出、负数/整数溢出、未知来源、双花、循环/未来引用、无关加工/超量余料、假部分失败/假 MAX、旧令牌、重复操作均零非法变更。保留原事务每阶段故障注入及事件重入。
6. 同一只读输入在服务端和客户端核心结果/消耗/余量一致；真实服务器逐步组装与见证一致；不同配方调用顺序不能污染全局 crafting player。专服运行不加载 Dist.CLIENT 类。

性能须比较 09-13 旧协议基线与新实现，不能只测悬停一个目标：

- 稳定原版目录，开/关筛选、全部分类、窄/宽搜索；空库存、1 原木、常用材料、混合路线；1/16/64 容器，1/2/8 个并发浏览客户端，RTT 0/50/150 ms。模拟连接压力与真实两台设备分别记录，不混称人工联机。
- 加入 1000/5000 条普通有序/无序测试配方压测目录规模（仅测试夹具，不宣布第三方兼容）；低配客户端与后台/最小化窗口记录帧时间，不能把服务器卡顿转移为客户端卡顿。
- 记录首次可用、50%/95% 已判定、全范围收敛、未知比例及错误漏项；“全范围收敛”只在所有范围项目取得确定结论时成立，已停止但仍未知另记。报告 P50/P95/P99/最大、100 次稳定范围切换与至少 5 次新会话冷样本。
- 分别计时扫描/复制/版本比对、目录归一化、闭包、精确求解/部分诊断、排队/往返、UI 更新、验证/提交；报告服务端完整 tick、客户端帧、网络字节、内存峰值、取消积压和每玩家最大等待。
- 普通原版稳定环境、RTT ≤100 ms 的初始目标：首次可用及可见页 P95 ≤500 ms，全筛选范围 P95 ≤2 s；同版本返回已计算范围不再搜索，下一次合并刷新即可展示。对照旧版本全范围耗时和服务端浏览 CPU，要求显著下降，并证明稳定浏览不会继续产生逐目标服务端搜索。
- 客户端调度须守 2 ms/tick 软片额和有界内存，服务端守原总预算；复杂目标/高 RTT/大目录单独报告，不为了过门禁提高预算、漏掉慢配方或把未知当全部完成。目标若实测不可达，重新评审瓶颈/数值并公开，而不是提前宣称达到。

### 8.1 M4.8 独立验收：消除大量被动搜索

09-17 第六批实施规则：2 ms 是整个客户端 tick 的同一个截止点，而非“每个目标 2 ms”或“每 tick 只能一个目标”。轻量目标结束后可继续派发，最多 64 次；每次仍经过原 3:1 选择器。普通目标分配 continuation 前必须调用同资源闭包的必要条件排除，不能绕过闭包批次造成多余根搜索。正例继续完整数量/容量验证；未知仍终止缓存。授权发布移到动态结果库重置之后，避免已匹配新快照仅因初始化顺序而多显示一 tick 待确认。没有放宽授权租期或执行校验。

当前真实压力夹具在 400 个实际 tick 调用生产浏览/详情 API，不模拟另一套调度器；反射仅观察根初始化与隐藏 continuation。网络压力将生产发送选择器与真实接收器组合，八份 4 MiB 共 1064 块，按四块/全服 tick、每玩家最多一块发送。此类模拟证明选择与接收时限相容，不证明世界扫描成本或八台设备的 RTT/帧表现。

- 稳定环境浏览当前范围及返回已完成分类，服务端逐目标被动请求/搜索计数均为 **0**；资源续期可以有受预算的扫描/比对和小型消息，不算零服务器成本。
- 同连接配方世代内，关/开背包、切分类的静态 Index 重建计数为 **0**；同动态版本和活动菜单范围内，100 次权限复查/范围切换导致的闭包重建和已完成目标完整重搜计数均为 **0**。关菜单后动态缓存按 4.3 释放，不把这一范围与静态复用混淆。
- FULL_ONLY 已充分排除后悬停/详情诊断，完整阶段调用为 **0**；UNRESOLVED 反例不能跳入部分。一次搜索跨多片，根初始化 **1** 次，累计状态/CPU 单调；耗尽后再过 100 tick 不新增被动尝试。
- 测量客户端静态构建/单次闭包成本，并明确是否触发 3.4/5.2 的二次优化门槛；不默认同时上关系同步和前向邻接。
