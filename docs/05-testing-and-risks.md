# 测试与风险

## 1. 测试分层

### 1.1 纯单元测试

规划器应尽量脱离 Minecraft 世界运行，覆盖：

- 数量守恒；
- 多层配方；
- 标签替代；
- 循环与可逆配方；
- 配方剩余物；
- 燃料组合；
- 部分完成前沿；
- 搜索预算和确定性；
- 组件不同的同类物品；
- 满输出容量与堆叠边界。

建议加入基于性质的随机测试：对随机生成的小型配方图验证“执行后资源 = 执行前资源 + 所有动作净变化”，并保证规划器在预算内终止。

### 1.2 GameTest

NeoForge/Minecraft GameTest 覆盖真实世界交互：

- 单箱、双箱、漏斗和不同侧面；
- 工作台有/无、刚被破坏；
- 炉类、燃料和经验；
- 区块卸载；
- 两名玩家争用最后一份材料；
- 玩家离开范围、死亡、切换维度；
- 配方数据包重载；
- 输出满、回滚和故障补偿；
- 掉落物归属与合并，进入第二阶段后添加。

### 1.3 客户端测试

- 原版背包、创造模式、不同 GUI 缩放和语言；
- 搜索框输入时 `C/Z` 不误触；
- 仅原版配方书，以及原版配方书与 JEI 同时存在；
- 两个前端的三态、目标配方、C/Z 结果和刷新时机一致；
- 多配方切换、长提示、组件 tooltip；
- 窗口缩放和无障碍颜色；
- 常见背包/饰品栏扩展模组。

### 1.4 专用服务器与兼容矩阵

至少测试：

- 纯 NeoForge 服务端；
- 客户端有 JEI、服务端无 JEI；
- 客户端无 JEI；
- 一个标准第三方 `IItemHandler` 容器；
- 一个领地/权限模组；
- 漏斗持续搬运同一容器；
- 低延迟与高延迟客户端；
- 不同权限等级玩家同时请求。

## 2. 核心不变量

每次测试和代码审查都要检查：

1. 客户端请求不能创造成功条件；
2. 输入、输出、剩余物和副产物数量守恒；
3. 事务要么完成，要么恢复到可解释状态；
4. 预览不修改世界；
5. 搜索总会在预算内结束；
6. 不加载新区块；
7. 不读取或同步无权访问的私有库存；
8. 相同快照、配置和目标得到确定计划；
9. 撤销不能增加任意一方的净资源；
10. 不支持的适配器不会降级为不受约束执行。

## 3. 性能预算

先把这些数字作为测量门槛，后续根据基准调整：

- 常规 8×4 范围、几十个容器的已缓存环境刷新：95 分位低于 5 ms；
- 简单/中等递归计划：95 分位低于 20 ms；
- 任何同步请求不得独占超过一个 50 ms 服务端 tick；超预算必须终止或分时；
- 玩家不打开相关界面且不发请求时，平均额外 tick 成本应接近零；
- 网络不发送完整附近库存，只发送目标、摘要和必要的显示数据；
- 服务器对每玩家和全局同时规划数都有限制。

基准场景应包含 1、16、64、256 个候选容器，以及 1 千、1 万级配方索引。记录平均值、95/99 分位和最坏情况，不只记录一次成功运行。

## 4. 风险登记

| 风险 | 严重度 | 可能后果 | 缓解与发布门槛 |
|---|---|---|---|
| 客户端伪造请求 | 极高 | 复制、远程偷取 | 服务端重扫重算、限流、专服对抗测试 |
| 多端点提交失败 | 极高 | 吞物或复制 | 托管区、稳定提交顺序、补偿事务、故障注入测试 |
| `IItemHandler` 模拟不纯/实现错误 | 高 | 外部机器副作用 | 熔断、黑名单、专用适配器、异常数量校验 |
| 绕过领地/锁 | 极高 | 公服失窃 | 权限 SPI、未知拒绝、首批领地兼容后再宣称公服安全 |
| 配方循环/搜索爆炸 | 高 | 卡服 | 深度/状态/时间预算、循环剪枝、随机图测试 |
| 配方组件处理错误 | 高 | 洗物品属性、复制附魔 | 精确组件比较、动态配方专用适配器 |
| 绕过配方副作用 | 高 | 不触发统计、进度、事件或模组钩子 | 规范化执行钩子、与手工合成对照测试、禁止盲目批量乘法 |
| 部分完成过度消费 | 高 | 玩家原料被意外加工 | 最大有用前沿、数量上限、默认确认、预览 |
| 瞬时熔炼破坏平衡 | 中高 | 绕过时间/产能机制 | 服务端开关、批量上限、公开语义差异 |
| 经验结算不等价 | 中 | 经验修补/事件差异 | 原版路径测试、初期不可撤销、文档说明 |
| 背包 UI 冲突 | 高 | 崩溃或槽位错位 | 不先替换菜单拓扑、M0 原型、兼容降级按钮 |
| 原版配方书内部实现变化 | 高 | 悬停识别或状态替换失效 | 公开事件优先、窄范围 accessor/注入、版本锁定、客户端回归测试 |
| 可见配方预览风暴 | 高 | 网络拥塞或服务端规划卡顿 | 只计算可见/悬停条目、环境世代缓存、合并请求、每玩家限流 |
| JEI API 变化 | 中 | 快捷键失效 | 隔离模块、公共 API、版本矩阵、无 JEI 回退 |
| 扫描过频 | 高 | tick 延迟 | 事件失效、短缓存、分 tick 预算、基准门槛 |
| 可达性判定不准确 | 中 | 隔墙取物或漏检 | 模式可配、保守超限、可视调试、阶段二上线 |
| 未生成战利品泄露 | 高 | 提前窥探/生成战利品 | 不主动解包、专门测试、默认排除未知状态 |
| 撤销与后续操作冲突 | 极高 | 复制或回滚他人物品 | 精确前置条件、失败即全拒绝、先限纯合成 |
| 世界交互泛化过度 | 高 | 跳过冷却、声望或事件 | 每种动作显式适配，不泛化任意右键 |

## 5. 故障注入清单

事务测试中主动在每个阶段制造失败：

- 预览后拿走一个输入；
- 第一端点提取后让第二端点拒绝；
- 提取后破坏容器；
- 输出插入时背包突然占满；
- 能力实例失效并更换；
- 玩家死亡或断线；
- 配方数据包重载；
- 适配器返回超过请求数的物品；
- 回滚时原槽不再接受物品；
- 客户端重复发送同一请求序号。

每个故障必须得到三类结果之一：世界不变、事务完整成功、进入明确记录的补偿路径。不得静默丢失。

## 6. 第一阶段发布门槛

- 所有核心不变量有自动化覆盖；
- 钻石镐、铁镐、桶剩余物、多配方和循环用例通过；
- 手工合成与自动合成的统计、进度、配方事件和物品回调对照通过；
- 连续至少 10 万次随机规划无超时、死循环或守恒错误；
- 双玩家竞争与故障注入无复制/吞物；
- 8 格默认范围基准达标；
- 仅原版配方书和安装 JEI 两种环境均可完成相同目标，且原版增强不会因 JEI 存在而消失；
- 一个第三方容器和一个权限模组通过明确版本的兼容测试；
- 瞬时处理、部分完成和未知权限策略均能由服务端配置；
- 已知不兼容项和语义差异写入发布说明。

## 7. 需要尽早验证的未知项

1. NeoForge 21.1.235 下对原版配方书有效网格、三态和悬停配方的最小注入边界，以及与热门 UI 模组的冲突面；
2. JEI 1.21.1 公共 API 能否稳定提供目标/配方上下文并承载三态覆盖，还是只能提供材料；
3. 原版和常见模组容器的 `IItemHandler` 是否能提供可靠模拟；
4. 领地模组是否公开无副作用的访问检查 API；
5. 炉经验采用经验球时的事件、经验修补和撤销边界；
6. 大型模组包中配方图规模与搜索预算的真实分布。

这些是阶段 0/第一阶段原型的研究任务，不应等到功能完成后才处理。
