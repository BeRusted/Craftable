# 测试与风险

## 1. 测试分层

### 1.1 纯单元测试

规划器应尽量脱离 Minecraft 世界运行，覆盖：

- 数量守恒；
- 多层配方；
- 标签替代；
- 循环与可逆配方；
- 配方剩余物；
- 燃料组合；
- 部分完成前沿；
- 搜索预算和确定性；
- 组件不同的同类物品；
- 满输出容量与堆叠边界。

建议加入基于性质的随机测试：对随机生成的小型配方图验证“执行后资源 = 执行前资源 + 所有动作净变化”，并保证规划器在预算内终止。

### 1.2 GameTest

NeoForge/Minecraft GameTest 覆盖真实世界交互：

- 单箱、双箱、漏斗和不同侧面；
- 工作台有/无、刚被破坏；
- 炉类、燃料和经验；
- 区块卸载；
- 两名玩家争用最后一份材料；
- 玩家离开范围、死亡、切换维度；
- 配方数据包重载；
- 输出满、回滚和故障补偿；
- 掉落物归属与合并，进入第二阶段后添加。

### 1.3 客户端测试

- 原版背包、创造模式、不同 GUI 缩放和语言；
- 搜索框输入时 `C/Z` 不误触；
- 仅原版配方书，以及原版配方书与 JEI 同时存在；
- 两个前端的三态、目标配方、C/Z 结果和刷新时机一致；
- 多配方切换、长提示、组件 tooltip；
- 配方页首次打开时不移动鼠标也会取得可见按钮状态；
- 成功制作后的定向刷新不会短暂显示错误的不可合成状态；
- 窗口缩放和无障碍颜色；
- 失败 Toast 位于原版通知区、重复请求只更新同一条，成功制作不产生通知队列；
- 配置页在标题界面、单人世界和远程多人中的可编辑状态；远程客户端不能把本地服务端配置显示成有效规则；
- 常见背包/饰品栏扩展模组。

### 1.4 专用服务器基线

至少测试：

- 纯 NeoForge 服务端；
- 客户端无 JEI；
- 漏斗持续搬运同一容器；
- 低延迟与高延迟客户端；
- 不同权限等级玩家同时请求。

JEI、第三方 `IItemHandler` 和领地模组进入第二阶段各自的兼容矩阵，不作为第一阶段核心实现的阻塞项。

## 2. 核心不变量

每次测试和代码审查都要检查：

1. 客户端请求不能创造成功条件；
2. 输入、输出、剩余物和副产物数量守恒；
3. 事务要么完成，要么恢复到可解释状态；
4. 预览不修改世界；
5. 搜索总会在预算内结束；
6. 不加载新区块；
7. 不读取或同步无权访问的私有库存；
8. 相同快照、配置和目标得到确定计划；
9. 撤销不能增加任意一方的净资源；
10. 不支持的适配器不会降级为不受约束执行。

## 3. 性能预算

M4 进一步受 [行为规格第 8 节](14-m4-spec.md) 的请求/整批/全服预算及 [实施计划](15-m4-implementation-plan.md) 的取证门禁约束。下列跨阶段测量目标不能被解释为给每个可见配方分别占用 20 ms；所有耗时均须区分扫描、求解、提交和通知，软截止无法抢占单次原版调用。

先把这些数字作为测量门槛，后续根据基准调整：

- 常规 8×4 范围、几十个容器的已缓存环境刷新：95 分位低于 5 ms；
- 简单/中等递归计划：95 分位低于 20 ms；
- 任何同步请求不得独占超过一个 50 ms 服务端 tick；超预算必须终止或分时；
- 玩家不打开相关界面且不发请求时，平均额外 tick 成本应接近零；
- 当前协议 6 不发送完整附近库存；规划中的 M4.8 只允许最小授权资源/容量值投影，禁止坐标、活句柄及未授权/私密信息，须有快照字节和版本安全门禁；
- 服务器对每玩家和全局同时规划数都有限制。

基准场景应包含 1、16、64、256 个候选容器，以及 1 千、1 万级配方索引。记录平均值、95/99 分位和最坏情况，不只记录一次成功运行。

M4.8/M4.9 专项门禁见 [筛选/客户端规划第 8 节](20-m4-filtering-and-client-planning.md#8-验证与关闭门槛)：不能把单项 P95 当成筛选全范围收敛，也不能只看服务端 CPU 不看客户端帧和同步成本。新增核心差分、超 256 项稳定版本、授权/容量变更、分块/会话/重载隔离、见证无关加工/双花/假部分及 1/2/8 客户端公平性测试。当前 53/65 不是这些新门禁的证据。

## 4. 风险登记

| 风险 | 严重度 | 可能后果 | 缓解与发布门槛 |
|---|---|---|---|
| 客户端伪造请求 | 极高 | 复制、远程偷取 | 服务端重扫重算；M4.9 完整见证改为新鲜真实配方/来源/贡献/容量重建，仍经原事务；限流、专服对抗测试 |
| 授权资源同步扩大信息披露（M4.8） | 极高 | 他人库存/私密组件泄露，撤权后误用 | 最小脱敏投影、玩家/连接/菜单绑定、发布前授权、限时复查；明确已发送信息不可收回 |
| 扫描号被误当内容版本或容量未入键（M4.8） | 高 | 反复重算或陈旧绿状态 | 完整投影比较、独立运行世代、容量/规则/权限入键、未知不伪装不可行 |
| 双算法/不安全线程迁移（M4.8） | 高 | 客服端结果漂移、帧卡顿、竞态 | 同核心/同容量器、纯值隔离、真实组装差分、有限 continuation；未审计回调不进工作线程 |
| 客户端见证夹带加工或假不可行（M4.9） | 极高 | 额外消耗、虚假余料、滥用部分准备 | 目标贡献/整批取整校验，部分失败由服务端证明，坏见证不触发全图回退，限制步骤/字节/算术 |
| 多端点提交失败 | 极高 | 吞物或复制 | 托管区、稳定提交顺序、补偿事务、故障注入测试 |
| `IItemHandler` 模拟不纯/实现错误 | 高 | 外部机器副作用 | 熔断、黑名单、专用适配器、异常数量校验 |
| 绕过领地/锁 | 极高 | 公服失窃 | 权限 SPI、未知拒绝、首批领地兼容后再宣称公服安全 |
| 配方循环/搜索爆炸 | 高 | 卡服 | 深度/状态/时间预算、循环剪枝、随机图测试 |
| 配方组件处理错误 | 高 | 洗物品属性、复制附魔 | 精确组件比较、动态配方专用适配器 |
| 绕过配方副作用 | 高 | 不触发统计、进度、事件或模组钩子 | 规范化执行钩子、与手工合成对照测试、禁止盲目批量乘法 |
| 部分完成过度消费 | 高 | 玩家原料被意外加工 | 有界有用前沿、完整批次与余量、显式双击/详情意图、EXPLICIT_SAFE 白名单、非安全计划确认、重复准备测试 |
| 余料实体创建失败 | 极高 | 输入已扣但余料未生成，或返还输入同时遗留掉落物 | 默认严格收纳；溢出实体与库存同次提交，逐生成位置失败/取消注入，精确清理本次实体后恢复 |
| 双击与网络回复竞态 | 高 | 长按误触或成品成功后又消费中间材料 | 按下/释放边沿、同菜单同目标关联、服务器核验首次真实结果、限时有界状态 |
| 物品链与 MAX 实际消耗不同 | 高 | 隐藏更换昂贵材料、共享库存重复计数 | 节点选择全局重算、手选约束不静默放开、联合最大计划、执行前改链警告与实际摘要 |
| 瞬时熔炼破坏平衡 | 中高 | 绕过时间/产能机制 | 服务端开关、批量上限、公开语义差异 |
| 经验结算不等价 | 中 | 经验修补/事件差异 | 原版路径测试、初期不可撤销、文档说明 |
| 背包 UI 冲突 | 高 | 崩溃或槽位错位 | 自有菜单契约、不替换玩家库存对象、兼容降级按钮 |
| 客户端/服务端菜单拓扑不一致 | 极高 | 错槽、物品复制、幽灵物品或断线 | 同构槽位表、菜单世代、重开策略、封包与 Shift 点击 GameTest |
| 原版配方书双重状态源 | 高 | 绿框与红框并存、过滤结果和 `C` 行为矛盾 | 权威状态进入集合语义，按钮/过滤/键位共用同一状态，不做叠加描边 |
| 原版配方书内部实现变化 | 高 | 悬停识别、目录或状态替换失效 | 公开事件优先、窄范围 accessor/注入、版本锁定、客户端回归测试 |
| 可见配方预览风暴 | 高 | 网络拥塞或服务端规划卡顿 | 只计算可见/悬停条目、环境世代缓存、合并请求、每玩家限流 |
| 配置所有权误导 | 高 | 多人客户端以为本地范围或自动行为已生效 | 客户端/世界规则分区、远程只读、同步有效规则摘要、集成服与专服对照测试 |
| 通知泛滥或遮挡 | 中 | 连续制作产生 Toast 队列、影响操作与无障碍 | 成功默认静默、失败按稳定令牌合并、复用原版通知时长与旁白设置 |
| JEI API 变化 | 中 | 快捷键失效 | 隔离模块、公共 API、版本矩阵、无 JEI 回退 |
| 扫描过频 | 高 | tick 延迟 | 事件失效、短缓存、分 tick 预算、基准门槛 |
| 配方知识缓存失真或无界增长（M4.7） | 高 | 重载后误用关系、假缺料、启动卡顿、磁盘/内存膨胀 | 完整语义指纹与引用/完整性验证、运行时世代隔离、单存档有界快照、未缓存不等于无解、损坏/超限回原索引；测试与性能门禁见 [知识设计](19-m4-recipe-knowledge.md) |
| 跨 JVM 序列化顺序不稳定（M4.7 实测） | 中 | 同配方却拒绝重启缓存，单 JVM 往返漏检 | 已针对金苹果效果 cures 真集合规范化；保留其他数组顺序，增加独立专服多次启动/真实 reload 门禁；不得放宽整个指纹 |
| 可达性判定不准确 | 中 | 隔墙取物或漏检 | 模式可配、保守超限、可视调试、阶段二上线 |
| 未生成战利品泄露 | 高 | 提前窥探/生成战利品 | 不主动解包、专门测试、默认排除未知状态 |
| 撤销与后续操作冲突 | 极高 | 复制或回滚他人物品 | 精确前置条件、失败即全拒绝、先限纯合成 |
| 世界交互泛化过度 | 高 | 跳过冷却、声望或事件 | 每种动作显式适配，不泛化任意右键 |

## 5. 故障注入清单

事务测试中主动在每个阶段制造失败：

- 预览后拿走一个输入；
- 第一端点提取后让第二端点拒绝；
- 提取后破坏容器；
- 输出插入时背包突然占满；
- 能力实例失效并更换；
- 玩家死亡或断线；
- 配方数据包重载；
- 适配器返回超过请求数的物品；
- 回滚时原槽不再接受物品；
- 客户端重复发送同一请求序号。

每个故障必须得到三类结果之一：世界不变、事务完整成功、进入明确记录的补偿路径。不得静默丢失。

## 6. 第一阶段发布门槛

- 所有核心不变量有自动化覆盖；
- 钻石镐、铁镐、桶剩余物、多配方和循环用例通过；
- 手工合成与自动合成的统计、进度、配方事件和物品回调对照通过；
- 连续至少 10 万次随机规划无超时、死循环或守恒错误；
- 双玩家竞争与故障注入无复制/吞物；
- 8 格默认范围基准达标；
- 无 JEI 的纯原版配方书环境可独立完成核心目标；
- 瞬时处理、部分完成和未知权限策略均能由服务端配置；
- 已知不兼容项和语义差异写入发布说明。

## 7. 需要尽早验证的未知项

1. NeoForge 21.1.235 下如何让 Craftable 权威三态完整替代 `RecipeCollection` 的集合筛选语义，并在不修改解锁进度的情况下建立 `ALL` 显示集合；
2. 原版容器在扫描、竞争和补偿阶段能否保持确定的守恒语义；
3. 炉经验采用经验球时的事件、经验修补和撤销边界；
4. 实体 3×3 菜单在客户端/服务端、创造模式、重生、切维度和工作台失效时的安全生命周期；
5. 大型原版配方/数据包配方图规模与搜索预算的真实分布。

JEI、第三方 `IItemHandler` 和领地 API 的未知项在第二阶段真正开始相应兼容工作时验证，避免它们反向支配核心架构。
